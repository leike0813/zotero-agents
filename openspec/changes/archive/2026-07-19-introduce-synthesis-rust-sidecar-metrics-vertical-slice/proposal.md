## Why

Rust migration R1 froze the language-neutral process contracts and canonical semantics, but Citation Graph Metrics still executes in the Node worker. Metrics is the smallest deterministic production-routed kernel that can prove the native toolchain, replaceable worker process, HTTP parity, packaging budget, and shared failure semantics before larger Synthesis capabilities move.

## What Changes

- Establish the minimal locked Rust workspace and one executable with `worker` and candidate `serve` modes.
- Make Rust the only active Citation Graph Metrics compute implementation behind the existing Node v1 HTTP/auth front door, without a per-request Node fallback.
- Preserve the single shared compute queue, deadline, cancellation, replacement, shutdown, and degraded fuse across the Rust Metrics backend and retained Node worker operations.
- Extend the cross-language corpus and worker framing so Node and Rust agree on strict Metrics DTOs, canonical bytes, hashes, ordering, and errors.
- Carry the verified target-native executable as an ancillary v1 runtime file and build five independent candidate artifacts under the native size budgets.
- Retain the TypeScript Metrics engine only as a frozen differential oracle; keep plugin routing, wire DTOs, promotion authority, runtime manifest v1, production data ownership, and non-Metrics kernels unchanged.

## Capabilities

### New Capabilities

- `synthesis-rust-sidecar-metrics-vertical-slice`: Defines the native Metrics protocol, worker/service candidate, five-target build evidence, and resource/size gates.

### Modified Capabilities

- `synthesis-citation-graph-metrics-engine`: Requires Rust Metrics v2 result parity while retaining TypeScript only as an oracle.
- `synthesis-citation-graph-metrics-production-routing`: Routes the existing authenticated Metrics capability through the Rust worker without changing plugin or HTTP contracts.
- `synthesis-sidecar-compute-worker-pool`: Preserves one admission/failure state machine across Node and Rust worker backends.
- `synthesis-sidecar-runtime-packaging`: Adds the verified Rust candidate as an ancillary v1 runtime file without introducing manifest v2 or formal XPI delivery.

## Impact

- Native implementation under `native/synthesis-sidecar`, plus locked Cargo metadata and five-target candidate CI.
- Cross-language compute corpus and worker framing, Node compute-pool backend selection, runtime packaging/freshness, and Synthesis migration documentation.
- Core 185, 193, 195, 198, and 218 remain the primary TDD seams; the frozen Stage 1 Node suite remains Core 175-218.
- No change to public plugin methods, `SynthesisClient`, authenticated HTTP DTOs, error codes, five-second deadline, graph promotion, database/canonical ownership, layout/build routing, or runtime pointer identity.
