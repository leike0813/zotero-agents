# Design

## Context

文献产物迁移由运行时按父条目串行执行。每组有独立的写入身份，迁移回执记录该组的结算结果，mutation authority 保存写入证据。

## Goals / Non-Goals

在可持久化回执的前提下，保证单组故障只影响该组。真实 dev profile 的重跑和缺失附件的恢复各自需要独立验证。

## Decisions

- **按回执推进。** 批处理保存当前组的结果后，下一组重新校验范围和来源。通用错误码仍用于诊断，未能确认结果的组保留为 `repair_required`。
- **按共享条件停止。** 宿主关闭复用组间停止入口。库变为不可写或必要回执无法持久化时，停止接纳新写入。mutation authority 返回不确定结果时，检查该操作的终态证据是否已写入。
- **在写入前识别缺失附件。** 旧附件读取区分文件缺失和其他 I/O 故障。文件缺失以 `not_found / read` 结算，组内原笔记及附件记录随重新扫描保留。

## Risks / Trade-offs

- 单组可能需要人工核对。回执保留失败阶段和可用的 authority 证据，后续组仍按各自的父条目执行。
- 共享存储中断时只能依赖最后一次持久化的结果。恢复通过重新扫描核对当前状态和未处理候选。

## Migration Plan

本次行为调整沿用现有回执结构。中断批次按当前源数据重新扫描，通过独立组的回执核对已完成及待修复结果。
