# Design

## Context

ACP 通过 Host Bridge 调用 Library、Evidence 和 Topic 搜索。词法扫描有来源数和片段数预算，向量保存在 sidecar 的已发布索引中，查询编码服务和 Zotero 来源由 Host 持有。

## Goals / Non-Goals

调用方沿用现有查询参数，并能从结果判断实际方法和覆盖范围。工作台提供直接测试语义检索和检查索引内容的入口。此次范围限于检索链路；Concept KB 与 debug snapshot 超时属于独立诊断。

## Decisions

- 在排名前按当前范围筛选已发布来源。Zotero 持有集合、标签和条目类型的成员关系；当向量命中超出词法目录时，按条目标识读取当前描述并核验原始 UTF-16 范围，随后才参与融合。
- Topic 采用规范章节名筛选和报告命中。结构化章节与 Markdown 都可提供可搜索文本；已有索引中的 `synthesis.md` 映射到 `synthesis_report`，回读仍使用原始资源身份。
- 工作台通过私有只读操作查询、浏览和展开片段。游标绑定发布版本与筛选条件。连接配置、凭据和索引维护继续由现有 Host 入口管理。
- 词法匹配保留原文位置映射。连续汉字使用相邻字对，标签命名空间从普通查询的可匹配范围中排除，完整标签支持显式查询。

## Risks / Trade-offs

核验时来源可能已经变化，此时省略受影响命中并报告覆盖缺口。语义检索可完成已发布范围的搜索，但词法预算和未索引来源仍会限制对全库的结论。既有 Topic 索引要通过维护纳入此前遗漏的结构化章节。
