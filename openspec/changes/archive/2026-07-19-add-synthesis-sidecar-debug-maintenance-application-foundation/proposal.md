## Why

The isolated Synthesis sidecar now owns every WS5 domain, checkpoint, durable-bundle, and WebDAV foundation, but it has no bounded debug/maintenance projection for proving that isolated state is coherent and operable. The final WS5 priority-8 slice must establish that private application, reuse existing maintenance owners, and close the WS5 exit gate without exposing a public route or moving production ownership.

## What Changes

- Add strict shared debug/maintenance contracts, repository projections, pure snapshot diffing, and an environment-neutral application for bounded status, schema, cache, operation, snapshot, paper, Topic, and profiler inspection.
- Capture repository basis transactionally, inspect bounded Topic canonical descriptors outside SQLite, and recapture the basis so concurrent change yields `superseded` instead of a mixed snapshot.
- Reuse Knowledge Checkpoint, Durable Bundle, and confirmation-protected reset owners; keep legacy JSON import, production profiler sources, Host paper details, and clean-install reset in production composition.
- Compose the application privately in Node after repository/canonical recovery and existing applications, then stop and drain it before its dependencies close.
- Preserve production `debugSynthesis*`, maintenance DTOs, method names, Host Bridge/CLI/MCP results, `108 methods / 1 direct consumer`, and absence of public sidecar routing.
- Complete the six WS5 exit gates and update current-state documentation so WS6 shadow parity becomes the next stage.

## Capabilities

### New Capabilities

- `synthesis-sidecar-debug-maintenance-application-foundation`: Defines bounded debug projections, coherent isolated snapshots, safe maintenance delegation, lifecycle, private composition, production compatibility, and WS5 closure evidence.

### Modified Capabilities

- `synthesis-maintenance`: Centralizes bounds, canonicalization, schema projection, and pure diff behavior while preserving the existing production maintenance surface.
- `synthesis-layer-doc-system`: Marks WS5 complete and WS6 as the next stage in current-state documentation.

## Impact

The change affects shared Synthesis contracts, repository and application packages, private Node composition, production debug/maintenance compatibility helpers, focused Core tests, runtime/XPI inventories, migration inventory, and Synthesis documentation. It adds no dependency, HTTP/RPC or worker operation, production persistence migration, unrestricted reset, arbitrary SQL/path/file inspection, shadow parity, cutover, release prebuild, commit, or branch change.
