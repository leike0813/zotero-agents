### 不能用来证明成功业务覆盖的三类清单

1. 230–235 的 surface parity 测试主要检查 roster、schema、corpus 标签及 fingerprint。corpus 中列出的 valid、basis_conflict、reopen、no_partial_write 等字符串是待满足的场景声明，不能当作对应业务已经执行。
2. 协议 corpus 中 valid:true/false 检查 DTO 是否符合 schema，不执行领域变更。例如 client-tag.json 的 tag-import-preview-result-nested-positive 不证明 import preview 实际不写入。
3. 229 的 “executes the closed production-operation scenario matrix through native composition” 调用 [synthesisProductionRouteScenarios.ts](../../../tests/helpers/synthesisProductionRouteScenarios.ts)。assertExpectedSemantic 仅检查 object/array/boolean、非空 object、expectedError，maintenance 只需属于 completed/failed/canceled/timed_out。它确实检查每次经过对应真实路由、read 的 SQL 零写入/持久状态不变/无 Host effects，但不能证明 mutation 成功、正确状态转换或读回一致。

closed scenario 的 11 个 expectedError 是：Concept patch/review/delete、Topic Graph accept/reject/review 均 unavailable；exportFilteredPaperArtifacts 为 invalid_request；getPaperArtifactManifest、readPaperArtifacts、resetSynthesisDatabase、debugSynthesisCleanInstallReset 为 unavailable。另有许多返回 object 的调用使用 missing ID 或 stale basis。后文以 **M** 引用该矩阵时，只认可上述有限证据。

## 状态机、业务序列与 OpenSpec 场景

OpenSpec 链接指向相关事实源；场景名用于审阅定位。规格中历史 operation 数量（例如 Tag 的 nineteen、WebDAV 的 nine）与当前 106 roster 不同，按实际代码核对，不据旧数裁剪业务范围。状态机中的 forbidden transition 是带条件的约束，不能与同名显式允许转换混淆。
