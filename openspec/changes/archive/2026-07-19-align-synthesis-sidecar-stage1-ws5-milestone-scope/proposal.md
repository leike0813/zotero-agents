## Why

The Stage 1 plan still mixes the final sidecar target, the original WS4/WS5
backlog, and the narrower foundation that is actually complete. This makes a
private isolated milestone read like production remote routing and ownership
have already shipped, while current code and active documentation correctly
retain production persistence, credentials, Host effects, and the default
client in plugin composition.

## What Changes

- Name the current milestone `Stage 1 / WS5 — Private Isolated Synthesis
  Foundation Complete` and state that it is not Stage 1 completion, production
  readiness, cutover, or real-machine acceptance.
- Reconcile the Stage 1 plan so WS5 closes only the private isolated
  application/repository/canonical/debug-maintenance foundation.
- Assign the remote-capable client, representative routes, process events, and
  shadow parity to WS6; assign production consumer routing and single-writer
  ownership transfer to WS7.
- Replace obsolete service-owned secret and export-registry tasks with the
  implemented secret-free WebDAV Host port and Host-owned export-delivery port
  boundaries.
- Normalize the milestone wording in current-state Synthesis documentation.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `synthesis-layer-doc-system`: Requires active planning and current-state
  documentation to distinguish the completed private foundation from WS6
  shadow verification and WS7 production cutover.

## Impact

This change affects the Stage 1 detailed plan, current-state Synthesis
documentation, and its documentation specification. It does not change
product DTOs, RPC, storage, dependencies, source behavior, runtime/XPI assets,
production ownership, historical baselines, or existing OpenSpec history.
