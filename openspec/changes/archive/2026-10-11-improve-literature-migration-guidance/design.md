# Design

## Context

动机见 [proposal.md](proposal.md)。Dashboard 已使用 Preact 区域渲染，迁移计划和处理选项由宿主持有；页面只接收有界快照。现有详情中的受影响条目只有首批摘要，不能通过客户端分页还原完整列表。

本设计记录本次已完成的实现。对应主规格已同步，change 中的 delta 记录相对于改动前基线的变化。

## Goals / Non-Goals

**Goals:** 保持步骤操作可见，让用户在明确后果和范围的前提下选择组策略，并能在长文本、窄窗口和大量受影响条目下完成审阅。

**Non-Goals:** 改变迁移分类、转换规则、写入确认、持久化格式或历史记录的数据保留范围；新增依赖或独立页面框架。

## Decisions

### 固定导航由向导统一持有

`MigrationsRegion` 在两列内容区外渲染一个固定页脚，统一承载返回、前进和最终迁移操作。返回最终审阅之前的问题组时恢复该组与原因筛选；没有问题组时直接进入最终审阅。忙碌状态禁用相应操作。

继续保留散落在组内容中的导航会让操作位置随滚动改变，且产生重复入口，因此移除重复导航。列表作为主内容滚动区，页脚和分页不随列表滚动。

### 复用现有控件与本地呈现状态

组策略使用更大的可点击卡片，沿用共享字阶和控件风格，分别展示标题、后果与选中状态。数据丢失提示按选项事实呈现；恢复组策略与单篇例外恢复分开处理。11 种语言通过现有标签投影提供文案，明确整次扫描中的组范围及失败后重新扫描的行为。

长文本使用有界摘要和原生可展开内容，展开事件不触发文献详情打开。窄窗口下详情替换列表并提供返回入口，历史区可以折叠。相比新增弹窗体系，这复用了现有页面与键盘交互机制。

文献列表共用分页组件。页码输入在 Enter 或失焦时提交，避免多位数输入中途跳页，并抑制 Enter 后失焦的重复请求。翻页重置列表滚动位置，保留选择与已打开的详情。

### 受影响条目由宿主按原始证据分页

新增只读 action `literature-migration-list-issue-items`，查询携带 `scanOperationId`、`candidateId`、`issueId` 和零基页码。`listIssueItemsPage` 验证归属后，从原始扫描转换结果分页，再格式化最多 25 条记录，保留既有单条文本上限。

成功结果包含查询身份、页码、页大小、总数、总页数和条目；失败投影也携带查询身份。宿主只保存当前问题查询，页面只接受与当前扫描、文献、问题和页码全部匹配的结果。一次只展开一个问题，切换运行或重新扫描清空查询。用户更改处理选择不会改变原始审阅证据。

客户端对首批摘要分页无法覆盖其余条目；一次传输全部证据又会扩大快照。因此采用宿主有界读取，不新增全量缓存或持久化证据副本。过期预览和缺少原始证据的历史运行明确报告不可用。

## Risks / Trade-offs

- 原始证据只在当前进程的预览中可用 → 历史运行保留既有有界回执，完整条目分页不可用时显示说明，不伪装成完整列表。
- 快速切换详情可能收到旧响应 → 成功与失败均校验完整查询身份，现有集成及浏览器测试覆盖交叉运行与过期响应。
- 长标题和展开内容可能挤压布局 → 浏览器测试覆盖宽窄窗口、详情展开和内部溢出，并检查键盘展开行为。
- 浏览器验证不能完全替代 Zotero 宿主 → 已检查 Chromium、Firefox；尚未进行 Zotero 实机验收或 XPI 构建。

## Migration Plan

随常规插件构建交付，无数据迁移、版本变更或依赖准备步骤。回退时将页面、wire contract 与宿主只读 action 作为同一变更回退；已执行迁移的数据仍遵循既有迁移生命周期。
