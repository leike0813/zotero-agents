# Design

## Context

动机见 [proposal.md](proposal.md)。历史目录在迁移后仍保留，正常更新只写新路径；启动迁移因此必须区分历史证据与当前快照。

## Goals / Non-Goals

目标是在保留既有迁移与完整性检查的前提下，允许更新后的 Topic 重开。此次不引入数据清理、额外迁移凭据或新的存储格式。

## Decisions

- 在 canonical-store 的现有启动迁移入口修复：新路径 `current` 存在时校验其 Topic 身份与完整表示，校验通过即采用；仅缺失时执行原有推广及 basis 验证。
- 保留历史快照校验与原始字节。拒绝以清理历史目录解决源码问题，也不增加迁移凭据：当前新路径已经是运行时权威，额外凭据会增加存量恢复条件。
- 扩展既有测试，通过公开的打开、读取和 receipt 接口验证连续重开，补充错误身份拒绝场景；真实材料只在隔离副本中验证。

## Risks / Trade-offs

- 当前快照可能损坏或属于另一 Topic → 保留路径、身份、hash 和内容完整性检查，失败时不回退或覆盖。
- 放宽新旧 basis 相等条件可能被误解为允许任意历史输入 → 历史候选的身份、路径及表示校验继续执行。
- 当前实例仍使用旧运行时 → 本次不安装或操作真实实例，后续需随原生运行时更新部署修复。

## Migration Plan

无需数据迁移。已从当前源码构建本机 sidecar，并对含冲突快照的隔离副本连续启动两次；本次只交付源码、规格和验证结果。
