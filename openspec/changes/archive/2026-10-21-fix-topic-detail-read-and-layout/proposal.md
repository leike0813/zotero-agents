# Proposal

## Why

Newly materialized Topics can be committed successfully but fail detail reads because sparse resolver selectors and text-form Concept evidence/relations do not match the native read DTO. A long Topic timeline can also widen the Reader grid until its centered body is outside the viewport.

## What Changes

- Normalize resolver selectors through one shared write/read adapter, retaining patch inheritance and typed public output.
- Preserve text and structured Concept evidence/relations across the Topic schema, TypeScript and Rust boundary.
- Constrain the Topic detail grid to the available Reader width while retaining timeline horizontal scrolling.
- Exercise the real native routes and browser geometry with synthetic regressions, then verify a fresh isolated real-library copy.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `synthesis-native-topic-workbench-surface`: materialized Topics remain readable with sparse resolver selectors and production Concept metadata forms.
- `topic-details-ui`: long timelines cannot push the Reader body outside its viewport.

## Impact

Topic application normalization, Topic domain contract-set/TypeScript/Rust DTOs, Synthesis Reader CSS, and existing native-route/browser tests. No database migration, dependency change, API method rename, real-library mutation, or plugin publication is required.
