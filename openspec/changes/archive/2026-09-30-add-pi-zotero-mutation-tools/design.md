# Design

## Context

Baseline: `2fa6bc0c85e9c27223c718b66eae0c1686f7ee94`. See proposal.md for motivation. Issue #26 C14 Q82–Q124, final W4 ordering and the final dryRun amendment define the scope. C13 owns reads; C07 owns admission; C08 owns private files; canonical Broker already owns mutation transactions and durable evidence.

## Goals / Non-Goals

Reuse those owners for all twenty-three reviewed mappings. This change does not expose generic mutation unions, navigation, permanent deletion, annotation/collection trash or new stored artifact schemas. Full Workspace E2E, cross-platform matrix and automatic restart recovery belong to later changes.

## Decisions

1. Extend the existing Native catalog with static business mappings, closed schemas and an enhanced authorization key. Reuse canonical mutation schemas for ordinary tools; semantic artifact schemas are projections of the existing contract set. `dryRun` is stripped before canonical preparation. Shared list bounds apply to logical request lists and expanded writes, not nested artifact payloads.
2. Add optional Gateway preflight. It returns a safe plan/digest and private execute/dispose closures. Prepare the entire batch before dispatch. Dispose on every terminal/deferred path. Pending JSON contains only the safe admission facts and digest. `continueCall` returns `{result,pending?}` so stale approval remains actionable. Denial is handled before possible execution.
3. The Broker calculates prepared domain identity from scope, input, observations, plan and actual file snapshot, and verifies declared manifests. Keep existing effect-time revalidation. Extend the trusted canonical control for semantic authoring instead of exposing storage operations or introducing another writer.
4. C08 prepares only regular public Workspace files with the existing path verifier, attachment stager and prepared-files owner. A narrow trusted return contains opaque prepared reference, prepared-files capability, safe manifest and cleanup callback. No external path permission or new source registry.
5. Catalog composition accepts trusted owner/evidence callbacks. Operation and generated reference identities are allocated once per logical owner/source-turn/call and durably recorded before dispatch. Continuations reuse that identity. Full domain receipts use canonical transcript facts exactly once; model results and Gateway evidence reference them. Existing canonical history is the durable fact source; no parallel mutation store.
6. Managed authoring reuses current References/Citation/Score fields without schema/basis wrappers. Missing References IDs are securely generated by Broker and persisted as call identity facts; explicit retained IDs must belong to the current parent artifact. Custom/conversation writes are full Markdown replacement with a discriminated create/update target. Preserve singleton, stale-basis and storage validation inside Broker.
7. Conversation replaces stale pending permission with the new request and publishes only its bounded plan. Workspace permission signatures include only visible plan and interaction facts; existing DOM identity tests cover isolation.

## Risks / Trade-offs

- Approval may outlive a file or item revision → re-preflight and renew permission; dispose stages while waiting.
- Effect succeeds but evidence persistence fails → unknown state and observation/reconciliation guidance; never retry by creating a new identity.
- Staging cleanup fails → preserve explicit cleanup-pending evidence.
- Artifact authoring could duplicate canonical validation → normalize in the existing Broker/managed-note owner and reuse the package validators.
- Real host infrastructure may constrain acceptance → record exact executable and targeted cases; do not claim the C20 matrix.

Run affected Node shards, type/lint/build and targeted real Zotero acceptance, then normal core where available. Update component documentation and handoff, verify against these artifacts, synchronize specs and archive with official skills. Do not commit or publish.
