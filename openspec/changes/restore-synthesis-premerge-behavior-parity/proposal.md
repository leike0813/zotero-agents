# Proposal

## Why

Stage 00 of create-topic-synthesis-prepare cannot export the complete artifacts for 24 resolved papers: cumulative Host reads exhaust the native ten-second deadline and are reported as invalid input. A second regression rejects 64–100 four-artifact papers despite admitting 100 paper refs. Existing migration evidence uses an earlier source baseline and does not establish complete pre-merge behavior parity.

## What Changes

- Audit every public service method at `77834172aa5aaf366bddfc538919fb844173a620`, the first parent of migration merge `35f2f77d2`, against its current semantic owner, consumers, approved changes, and executable evidence.
- Preserve the synchronous artifact interfaces with a manifest-owned 120-second operation budget and compatible CLI/MCP waiting windows.
- Align delivery capacity with 100 papers, four artifact kinds, and one manifest while preserving content and path bounds.
- Preserve timeout, unavailable, validation, conflict, and internal failure categories through native and Host Bridge boundaries.
- Repair confirmed regressions, extend existing production-route behavior tests, and exercise the Planned Topic prepare handoff in isolated Zotero acceptance.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `synthesis-native-production-routing`: reconcile the actual pre-merge method inventory and preserve typed artifact deadlines through every caller.
- `synthesis-host-export-delivery-port`: derive entry capacity from the admitted paper/artifact capacity.
- `synthesis-native-artifact-library-debug-surface`: prove complete multi-paper export, failure classification, and successful prepare consumption through production participants.

## Impact

Shared Synthesis contracts and policies, Rust runtime and CLI transport, native client composition, Host Bridge/MCP adapters, existing behavior tests, migration fixtures, audit evidence, and operating documentation. No production legacy fallback, dependency installation, Git commit, or release is included.
