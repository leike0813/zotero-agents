# 导入文献包

## 这个 Workflow 做什么？

将 [导出文献包](../export-literature-bundle/README.md) 生成的 ZIP 导入当前 Zotero 文献库，恢复其中的父条目、标签、附件、笔记、笔记内嵌图片，以及同一文献包内父条目之间的关联关系。

适合在另一台设备、另一套 Zotero 文献库或协作者提供的文献包中恢复完整文献。它不是 [研究包导出](../export-research-bundle/README.md) 的导入入口。

## 前置准备

- 准备由“导出文献包”生成的 ZIP 文件
- 确认当前打开的是需要写入的 Zotero 文献库

导入前会验证文献包类型和版本、归档路径、文件清单、文件大小与完整性。验证失败时不会改动 Zotero 文献库。

## 怎么输入？

- **无需选中条目**：从 Dashboard 直接运行此 workflow
- 在文件选择窗口中选择一个文献包 ZIP
- 当前选择不会作为导入目标匹配条件，也不会用于去重

如果当前视图选中的是该库中的真实 collection，新建父条目也会被加入该 collection；否则会导入到当前库的根级位置。

## 执行方式

全自动，本地执行，无需后端或模型。选择 ZIP 后，插件先完整校验文献包，再逐个恢复其中的父条目。

## 需要多长时间？

取决于文献包的条目数量、附件大小和本地磁盘读写速度。包含大型 PDF、图片或大量笔记时，导入时间会相应增加。

## 产出什么？

每次导入都会新建 Zotero 条目图：

- 恢复父条目的书目信息和标签
- 导入可用的本地附件与 Markdown 附件的配套本地图片
- 恢复 URL 附件、子笔记和笔记内嵌图片
- 恢复同一文献包中成功导入父条目之间的关联关系

导入不会复用原 Zotero 的条目 ID 或 key，也不会与现有条目去重、合并或覆盖。因此重复导入同一个文献包会得到独立的新条目图。

若某个父条目导入失败，插件会清理该父条目及其本次新建的子项，并继续尝试导入文献包中的其他父条目。缺失文件、清理失败或关联恢复失败会作为警告报告，结果可能为部分完成。

## 参数说明

无用户可配置参数。

## 模型建议

无需后端模型。

## 依赖

- 不需要后端连接
- 仅依赖 Zotero 本地存储与文件访问权限
