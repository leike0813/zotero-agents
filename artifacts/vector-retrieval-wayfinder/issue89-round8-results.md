## 实验对象与比较口径

语料仍为冻结的 4B／MRL 1024、12 个中英配对查询。2k 压力集复制原 86 篇文献改变身份，含 248,806 片段、2000 文献身份及原 4 个 Topic，并非 2000 篇独立文献。此次只测第七轮两个非空范围：intersection 为 46,813 行／185 对象；union_intersection 为 69,198 行／231 对象。它们是文献过滤范围，不构成 Topic 或真实跨库验收。

范围 anchor 限定在原始 12,646 行内；原 SQL、索引 SQL 和冻结 metadata 投影的 eligible 身份及顺序一致。各正式查询都重新准备范围，不缓存 eligible 结果。metadata、取数与过滤共用一个只读 SQLite transaction；保存图和 oracle 不属于该 transaction，输入一致性继续依赖冻结工件及下面的逐位验证，不能解释为生产发布机制。

比较三条路线：全局 HNSW 加 Bitmap selector；按 eligible 全局身份升序构建的范围内 HNSW；直接搜索该范围 HNSW 的 IndexFlatIP storage。Flat 路线借用已有向量存储，不另复制 Flat 索引。HNSW 参数均为 M16、efConstruction100、seed89、单线程、Faiss 1.13.2；范围图的 local ID 映射回全局片段身份。索引大小、编号与 topology 均改变，结果不能全部归因于 selector。

固定候选预算为 400／1600／6400／16384，HNSW 的 efSearch 为 `max(256,budget)`。每预算独立搜索，不累计、不根据数量或排名停止，也不根据 oracle 调参。三个路线的候选都从 SQLite 实际取向量，以第六轮的顺序 float64 dot／norm 重算 float32 距离，按距离及稳定身份聚合 Top100；Top25 是这个结果的前缀。

**FlatIP 的精确是其 float32 inner product，不是 Rust 顺序 float64 余弦参照。**本轮没有改变距离契约。关于两类索引能力的来源：[Faiss 官方索引说明](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)、[固定版本 HNSW 参数定义](https://github.com/facebookresearch/faiss/blob/v1.13.2/faiss/impl/HNSW.h)。

每配置预热一次，12 查询 × 3 次，三个路线轮换次序，共 24 个配置、864 次正式执行。质量按每查询第一轮取宏平均，即 12 条相关查询；三次是计时重复。对象召回相对完整 Rust oracle，不是人工相关性准确率。最佳片段覆盖检查 exact Top-k 对象的最佳片段是否进入候选，不能用对象命中替代证据命中。

6400 档时，交集的全局路线有 2 查询未凑齐 100 对象，两条子集路线均凑齐；并集再交集也是 2→0。全局／16384 的交集仍有 2 个短查询，而并集再交集虽然全都返回 100 个，对象召回最差仍为 68%。合法且数量完整不能证明结果正确。

相同请求预算也不等于相同重排工作量。6400 档的交集全局路线实际有效候选数中位为 2148，范围 6–5524；并集再交集中位为 6228，范围 184–6400。两条子集路线每查询都返回 6400。因此总时间差同时包含候选生成差异和实际重排数量差异，不能单独归因于搜索速度。

固定版本 HNSW 的普通搜索在加入结果时检查 selector，仍将不满足 selector 的节点放进导航候选；搜索预算因此不等于访问同样数量的 eligible 节点。范围图使所有导航节点都在 eligible 内，但也改变了拓扑和局部编号。本轮观察支持比较子集策略，不能据此声称已经单独证明每种损失的内部原因。[Faiss 1.13.2 HNSW 搜索实现](https://github.com/facebookresearch/faiss/blob/v1.13.2/faiss/impl/HNSW.cpp)

## 精确截断对照：并非只有图搜索误差

正式运行结束后，另取 Rust oracle 的 exact 片段 Top-budget 再聚合对象。这个离线控制排除图搜索及 float32 候选内核误差，只测片段截断；没有查询时间，不是算法可读取的捷径。

并集再交集／1600 即使片段候选完全精确，对象 Top100 也只有 74.58%。因此范围图不能消除对象聚合所需的 overfetch，候选预算必须相对对象结果验证。6400 的 exact 截断和 Flat 都补齐，而子集图仍缺 8 个 Top100 身份，表明该输入上图候选还有额外损失；没有把不同预算之间的提升全部归给图。

复制同分身份也有影响：并集再交集／1600 的 Flat 严格对象 Recall@100 为 73.92%，完全相同 Rust float32 边界距离可互换的 tie-aware 指标为 74.58%。查询序号 2 的严格值为 92%、tie-aware 为 100%；序号 5 的 Top25 为 92%／100%，但 Top100 仍只有 36%／36%，不是所有损失都能用同分解释。严格身份指标继续保留，tie-aware 不代替最佳片段覆盖。

## 查询成本与构造成本分别看

6400 档时，子集 Flat 的范围准备中位为 112.752／128.825 ms，搜索为 20.276／28.039 ms，范围检查加取数及实际重算为 119.030／118.972 ms，聚合约 1.38 ms。各阶段中位不保证相加等于总中位；范围枚举和重排仍占主要成本，不能只报 Flat kernel 的 20–28 ms。

`prepare_ms` 只包含范围准备调用。范围等值断言、query 切片、局部 ID 映射或 Bitmap 构造属于 `search_ms`；候选范围断言属于 `rescore_ms`。分段不是纯 kernel 计时。距离逐位核验、聚合身份核验及质量指标全部在总计时结束后，未用预计算分数冒充重排。

正式查询在已物化的向量上运行，单次范围构造成本如下。

| 交集 | 1505.824 | 2611.695 | 24021.113 | 98.494 | 198501014 B，189.305 MiB | 374504 B |

初次 eligible 准备及其两路身份核对发生在构造计时之前，未记录单次时间；本表不含这部分，也不能用后续 warm 查询的准备中位替代。`build_work_ms` 只计取数、校验／归一化、建图，为 28.139／55.871 秒；包含坐标核验和保存的 `measured_setup_ms` 为 28.300／56.087 秒，仍不是完整动态请求成本。校验／归一化是单次合并采样，两范围的差异不能解释为可靠规模规律。

Flat 在本实验借用子集图 storage；如果单独选择 Flat，不需要支付 HNSW 建图成本，但仍需准备或访问相同 normalized 向量。仅 float32 子集向量负载分别为 182.863／270.305 MiB，未证明动态物化、缓存更新或另一实现的内存成本。不能给每种标签／集合组合持久化一份图来绕过组合数量、basis 和更新问题。

按相同预算的 36 对查询配对，子集图的总时间节省中位在两范围、四预算均为负，没有正向延迟摊销点。它更慢的一部分来自召回更多候选，不能把较快但漏项的全局路线称为等价替代。子集 Flat／16384 在并集再交集的总时间配对节省中位为 66.507 ms、12.47%，交集却慢 71.653 ms；质量仍不同。这些差值与分布在 JSON 中，不以两列各自中位之差冒充配对结果，也不据此作经济或生产盈亏结论。

## 验证与资源边界

子集取数后归一化坐标与原全局图的保存坐标全部逐位一致，共 **118,795,264 个坐标**。这是坐标比较数，未乘以每坐标 32 位。两份图与 mapping 保存后重载，400 档 12 查询的候选身份和顺序一致，共 **24 次重载对照**。

864 次正式执行的候选距离共 **4,584,801 次逐位比较**，全部匹配 Rust oracle。计时后获胜片段顺序与参照一致，重复执行的候选及获胜片段身份一致，全部已返回候选通过硬范围检查。距离次数包含重复身份，不是全库新增唯一样本；零违规也不能证明没有漏召回。

独立审查指出正式结果原先只保存去重候选数量。运行结束后用同一保存图、映射、查询和参数额外重放 **288 次搜索**，检查原始有效 ID 的重复、`min(budget,eligible)` 数量上限、范围和 Flat 填满预算；全部通过，原始有效数量等于正式去重数量，没有重复。它是事后重放证据，没有把它称为原始运行的 raw-ID 捕获。

入口的红→绿自测覆盖局部到全局映射、越界、重复局部身份、非法 mapping、空候选／空范围、单行范围和候选预算大于 eligible；既有范围并集／交集、距离和聚合检查继续复用。自测、Ruff lint／format、Prettier、864 次计时／质量统计一致性、公开结构脱敏检查通过。无变更的 Rust oracle 没有重复构建或重测。

全局图重载为 1193.988 ms，metadata 加载 635.244 ms、11,942,688 B；正式主进程约 **336.36 秒**，在 10 分钟上限内。加载后 RSS 为 1,106,216 KiB，最终 RSS 为 1,127,436 KiB，最终报告的 VmHWM 为 1,692,684 KiB。内存属于整个 harness，包含全局图、局部图、向量数组、重载副本、oracle、metadata 和分配器保留，不是局部图独占内存。未测 staging、备份或构造并发峰值。

共享 Python SQLite 为 3.45.1，Rust oracle 沿用 bundled 3.53.2。主机非独占，没有清缓存或固定 CPU／磁盘负载，没有不同 seed／插入顺序的重复建图；本轮不是生产 P95、Rust 引擎性能或任意范围泛化证据。输入都是先前查询和复制文献，没有人工相关性金例、独立查询或新增语言验证。
