# #89 第二轮：1024 维参考配置

用户已同意以 Qwen3-Embedding-0.6B / 1024 维为主要本机参考，4B / 1024 维为质量对照，并已将 0.6B 拉取到本机和远端。执行采用上轮获授权来源库的现有只读快照，不再读取或修改来源库。所有正文、模型响应、查询、向量与实验 DB 留在新的 `.scaffold/test/` 忽略目录。

本轮先回答三个问题：1024 维在相同全文片段密度下的空间与完整文献检索成本；0.6B 在 P4、CPU、4090 上的实际编码成本；相较 4B / 1024 和已有 4B / 2560 的内容命中差异。模型质量仍须人工确认，Agent 审阅或排名交集不会记作金例验收。

## 文件范围

- `issue89/corpus.py`：复用原有请求/数值校验，允许实验调用显式指定模型和维度，新增模型支持的 MRL 截取归一化及其行为检查。原有切分、原文位置和生产契约保持当前含义。
- `issue89/round2.py`：隔离工件准备、同查询候选的编码/派生、硬件暖机与正式样本、脱敏对照统计；作为本轮实验入口复用现有语料和基准，不创建生产服务或接口。
- `issue89/benchmark.rs`：gpt-6-luna 子代理修正稳定同分选择，优化重复计算；仅修改实验源码。距离、硬范围和稳定身份条件不放宽，任何正确性修复成本计入时间，不能把任意超采样称作精确结果。
- `issue89-round2-results.md/json`：本轮可复现方法、明确判断、实际结果及剩余缺口。上一轮结果保留，不重写历史测量。

## 固定条件与顺序

1. 同一 12,646 无重叠片段、相同 12 条中英查询、相同查询指令；float32、余弦，不量化保存向量。0.6B 重新编码；4B / 1024 对已有 2560 维按模型 MRL 能力取前 1024 维并重新归一化，文档和查询使用同一方法。这是显式实验编码要求，不是静默降维。
2. 核实两端模型制品及实际响应；先完成编码和 Rust 构建，再开始本地性能测量。每候选生成独立 DB，所有路线共享该候选完全相同的向量和查询；编译/硬件/检索/本票其他压力任务不与正式计时重叠。保留已有机器工作，逐项记录背景负载，不声称独占机器。
3. 先检查同分身份与数值/范围/聚合，再测真实规模及 2k 压力。k=25/100，每范围每路线至少 30 次。完整文献聚合与片段检索分别记录。正确性或最低延迟未满足时，先解释根因，不直接铺开 10k/25k。
4. P4、CPU、4090 对相同四段全文和单条查询测量；明确冷加载、暖机与正式样本，固定上下文/线程等实验设置。0.6B 与 4B 都测，暖机不能混入正式请求统计。测后恢复本机测前已加载的 GPU 模型；不停止用户其它任务，不变更持久 Ollama 配置。
5. 内容比较使用同语义查询及完整候选的文献聚合。私有结果保留正文便于审阅，公开只保存统计；先报告模型/维度变化的实际差异，不能用排名一致性替代相关性。

交付应能判断哪个配置值得继续作本机参考、当前精确检索实现是否满足 2k 最低目标，以及 sqlite-vec 增益是否覆盖其代价。#88 生产来源核验、maintenance 生命周期、业务 Repository 并发、完整质量验收与七平台交付仍是独立必需证据；本轮不以隔离实验关闭 #89。
