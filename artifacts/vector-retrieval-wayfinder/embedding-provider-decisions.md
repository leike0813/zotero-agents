# Embedding provider 已确认要求

本文件汇总[embedding provider、索引空间与配置契约](https://github.com/leike0813/zotero-agents/issues/81)的当前决议。它是规划记录，具体 DTO/schema 和生产实现由后续 OpenSpec 承接；当前没有运行模型或实施索引操作。

## 服务与配置

- 首版连接用户提供的本机、局域网或远程 HTTP embedding 服务。模型安装、下载及 CPU/GPU 选择由服务管理，不内置推理环境。
- 首版协议为 OpenAI-compatible Embeddings 与 Ollama 原生 /api/embed。协议兼容不证明模型编码语义及实际响应已经满足要求。
- 配置在 Synthesis Home 索引管理区域管理，具有独立 embedding 用途，不绑定 Agent 聊天默认模型。连接地址、认证等通用事实尽量复用既有基础能力，Host 继续持有配置、凭据、网络及取消。
- 可以保存多套服务配置，当前 Synthesis 数据根只维护一个生效模型和一套正式索引，不按 Library 分配模型或进行多模型联合检索。用户为同一模型指定主服务和有序备用服务，后台按顺序使用兼容服务；不自动纳入全部已保存配置。
- 普通字段为名称、协议、地址、认证及模型 ID；高级字段为 query/document 前缀和服务支持的输出维度。前缀默认空，实际模型要求通过明确配置及预设表达，不根据名称猜测。
- 模型 ID 可手填，服务模型列表可辅助选择。显式测试使用少量固定文本检查 query/document 响应、维度及耗时，不读取真实库，不替代项目检索质量验收。
- 开发调研常见模型并预制可靠配置，保留自定义能力，不指定唯一默认模型。预设更新只影响新建配置，不自动改写已保存设置。

## 模型身份

用户明确采用“模型 ID 一致即可”：

- 以保存并生效的模型 ID 作为模型身份，与索引记录的模型 ID 匹配。
- 不要求固定版本证明、模型制品 digest、仓库 commit 或逐次响应版本证明。服务缺少不可变版本信息不阻塞配置启用或索引构建。
- 索引绑定模型 ID，不绑定服务配置 ID、供应商、地址或凭据。模型 ID 匹配之外，继续核对实际输出维度及配对 query/document 编码要求；同模型兼容服务切换不重建。
- 服务在同一模型 ID 下替换模型而保持相同响应形状时，首版不保证能检测该变化；不增加版本证明、探针指纹或逐请求检查机制。用户知道模型已替换时可通过既有动作重建。
- 预设按实际服务模型 ID 及经过核查的编码设置提供，仍须进行服务适配、质量和性能验证。

相关研究：[模型预设配置](./embedding-model-presets-feasibility.md)、[provider 接口差异](./embedding-provider-feasibility.md)、[Ollama 版本绑定核查](./ollama-model-version-binding.md)。研究中的版本能力事实不构成产品准入条件。

## 编辑、重建和切换

| 动作 | 已确认行为 |
|---|---|
| 保存新服务配置 | 只保存，不立即切换服务或索引 |
| 切换同模型兼容服务，或修改其地址 | 使用已有索引，不重建 |
| 使用另一模型或编码设置整体重建 | 语义检索整体不可用；不维护旧索引编码，可独立词法方法继续使用 |
| 重建成功 | 模型及编码设置与索引一起切换，旧查询游标按既有依据失效规则处理，清理旧向量索引 |
| 发布前重建失败或取消 | 保留已完成构建工作，语义检索保持不可用；用户重试完成并整体发布后恢复 |
| 成功发布后旧数据清理失败 | 新索引语义检索继续可用；任务成功并附清理问题，用户通过现有维护入口只重试清理 |
| 切回之前模型 | 需要重新构建，不保存逐模型历史索引 |
| 修改名称、密钥、超时等连接运行参数 | 保存后使用，不重建向量 |
| 修改模型、维度、query/document 前缀等编码设置 | 保存为待生效配置，通过重建切换 |
| 修改索引纳入的库范围或来源类别 | 保存为待生效范围，用户明确启动重建后整体切换；复用模型、编码及来源版本仍兼容的已有向量 |

维护对象是一套正式向量索引及一次重建任务。重建额外空间计入维护预算，空间不足时明确报告并保留旧索引。Library 范围隔离继续遵循已确认查询契约。

按 [生命周期 Q10](https://github.com/leike0813/zotero-agents/issues/82#issuecomment-5980565013)，新索引成功发布后，旧数据清理失败不撤销发布或关闭语义检索；保留待清理记录，用户只重试清理，重启不自动执行。

索引范围调整遵循 [生命周期 Q14](https://github.com/leike0813/zotero-agents/issues/82#issuecomment-5980679290)：保存待生效范围，用户明确启动重建，复用仍兼容的向量，完整完成后范围与索引一起发布；已有构建须先停止才能替换目标。

重建期间能力按 [索引生命周期 Q5](https://github.com/leike0813/zotero-agents/issues/82#issuecomment-5980407180) 修订：旧模型可能不可用，整体重建不依赖它继续编码或查询；按 [Q6](https://github.com/leike0813/zotero-agents/issues/82#issuecomment-5980431165)，失败/取消后也不自动恢复旧语义查询，用户重试完成并发布后恢复。

## 关闭与删除

- 关闭 embedding 停止向量增强，保留当前配置和索引；搜索使用可独立执行的词法方法。
- 重新启用时，兼容且就绪的索引可继续使用，不因开关动作重建。
- 删除服务连接保留模型索引；暂时没有可用兼容服务时停止向量增强，独立词法能力继续工作。以后接入同模型兼容服务时，仍兼容且就绪的索引可以恢复使用，不因删除/新增连接本身重建。
- 维护任务仍在使用配置时，先由既有任务 owner 完成结束或取消，再删除依赖。

## 文本范围、长度和费用

- 重建启动前展示目标服务、索引范围、来源类别和待处理规模。
- 仅发送该范围需要编码的已纳入文献材料或 Topic 文本。查询发送 query 及必要编码前缀，不额外附带 Zotero 身份、本地路径或原始文件。
- 启用后自动增强查询沿用该配置，不逐次确认。
- 只有可靠价格和用量依据齐备时才估算金额，否则费用未知；服务返回用量时记录实际值。
- 超长文档片段继续切分，保持来源版本及原始文本范围可定位。
- 超长 query 保持完整，不截断，使用完整原 query 的独立词法搜索并说明增强不可用；没有可执行方法时为 unavailable。
- 长度依据实际模型/服务能力处理，不能用字符数冒充精确 token 数。

## 失败与恢复

- 每条输入必须唯一对应一条有效向量，校验数量、对应关系、维度及有限数值。明确的结果索引允许重排；缺少/多余向量、对应关系不明或无效向量使该请求整体失败，不猜测位置、不写入该响应中的部分向量。
- 查询按用户指定的主/备用服务顺序尝试，每个服务最多一次，共用整次查询的时间预算；切换服务不重置期限。全部失败或预算耗尽时按既有独立方法回退，没有可执行方法时为 unavailable。
- 构建可切换同模型兼容备用服务，每批总尝试次数最多三次，服务切换计入该总次数。退避并尊重服务等待提示；认证失败、模型不存在和配置错误不在同一服务重试。
- 无效响应按上述预算尝试兼容备用服务。达到上限记录失败，其他批次此前已完成的工作保留；后续恢复由既有维护 operation 持有，不重做整个索引。
- 索引构建、发布、取消、继续、重启及清理的详细恢复规则由[索引生命周期票](https://github.com/leike0813/zotero-agents/issues/82)承接，不另建生命周期 owner。
