# #89 第三轮：4B／1024 扩容与正文证据

用户已授权继续测试，固定 4B／1024，并确认同时进行 10k／25k 性能和参考条目挤占正文证据的调查。复用第二轮的只读向量、查询和 86 篇真实文献／4 个 Topic；扩容只复制真实片段及变更测试身份，不重编码，也不假称独立文献金例。

## 工件和执行

- 新增 `issue89/round3-scale.rs`：复用原 benchmark 的 SQLite／向量／范围／参照距离／建库函数，增加只在已有实验库上运行的规模测量入口。分别测 Rust 片段、Rust 全范围完整文献聚合，以及没有冗余全范围 ID 筛选的原始 vec0 KNN。原始 KNN 不作为参照精确结果；全范围聚合不靠片段 Top-k。k=25／100 每路线 30 次，固定轮换 12 查询，记录每次耗时及身份差异，不增加生产 API。
- 新增 `issue89/round3-quality.py`：结构证据分类，比较现状与只排除完整书目候选的保守策略；不确定或混有正文的片段保留。另设完全处于参考区的排除对照，允许排除截断段落和区内解释，用于测试保守策略的覆盖局限及更宽规则的误伤。三个对照在正式内容排名生成前确定。固定文档盲标不变，新最佳片段重新审阅。关键分类边界先写行为检查，质量脚本和人工／Agent 标签仍分开。
- 新增 `issue89-round3-results.md/json`：方案、工具链、统计、限制和下一步判断。旧轮结果保留，不覆盖私有输入、现有未提交改动或原始来源库。

大型实验库采用新建且权限受限的 `/tmp` 目录，该磁盘可用约 120 GiB；工作区本身可用约 38 GiB，不能勉强容纳全部大库。首先在同一 `/tmp` 磁盘重测 2k，然后串行构建和测量 10k／25k。每档分开保存普通 BLOB 表与 sqlite-vec 双表的建库时间和空间。测量连接计时在各自实际库上进行，不把双表里的普通表测量冒充独立普通表测试。磁盘、背景负载、RSS、末尾 WAL 和构建期间采样空间分别记录；空间采样峰值不当作精确瞬时最大值。

本轮不同时运行本票编码／编译／质量矩阵／性能任务，现有机器任务保持运行。两个候选路线交替先后顺序降低缓存偏差；不清 OS 页缓存，不声称独占机器。查询向量已预生成，检索耗时不含 embedding。规模未达 p95 1 秒目标／2.5 秒最低要求时如实报告，但继续取得用户本次要求的规模证据；资源校验失败则保存该档拒绝证据，不删旧工件释放空间或伪造测量。

内容实验采用原始真实语料，不用扩容副本做相关性结论。剔除策略仅作受控实验，不预定产品规则。子代理 gpt-6-luna 作独立方法与片段审阅，结果明确标注非人工金例，不从排名交集推导质量、不从部分标签算 Recall/NDCG。

隔离数据与报告不完成 #88 来源核验、正常 Repository 并发、maintenance 生命周期或 #90 七平台验收，#89 继续开放。本轮不修改生产源码、schema、依赖，不提交或切换分支。
