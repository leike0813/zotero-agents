# #89 第十轮：新查询与候选预算

用户授权继续试验，baseline `84b3028dba8f5f3b8437f3aa237bf0fec2e68820`。新增本计划、`issue89/round10-holdout.py` 和结果 Markdown／JSON；复用第九轮常驻 Flat、第六轮只读 SQLite、Rust oracle exporter 及公共评分辅助函数。私有输入、查询文本和逐次结果位于全新 `.scaffold/test/issue89-round10-20261005/`。

先冻结 32 条自撰查询：中文、英文各 16 条，主题及表达不沿用旧 12 条，也不制作互译配对。查询生成者不读取私有语料或候选结果；加入少量无关领域查询，只考察算法相对 oracle 的身份与证据覆盖，不把它们当作人工相关性负例。此处独立指新编且未参与前轮预算选择，不代表统计独立、真实用户分布或人工金例。

查询经相同 Qwen3-Embedding 4B、指令前缀、2560 维输出与 float64 前缀 L2 缩减至 1024 维；输入禁止截断，num_ctx=4096。保存模型观测和嵌入参数，冻结后不改查询。原文档矩阵沿用，不重建、不重新嵌入。接口依据：[Ollama embed 文档](https://docs.ollama.com/api/embed)。

预先固定三个预算 1600、6400、16384，主检验为 6400。三个范围沿用 all、intersection、union_intersection。每请求重新准备 eligible，直接评分常驻矩阵中的指定行，以 float32 分数及全局身份选候选；从 SQLite 重算顺序 float64 余弦、转 float32，按最佳片段聚合对象 Top100，检查 Top25 前缀。路由与预算不读取 oracle，不按查询调参。

每范围／预算预热一次；32 查询 × 2 次 × 3 范围 × 3 预算，共 576 次正式执行，单线程，同一只读快照。第二轮反转预算顺序、轮转查询顺序以减轻固定顺序影响，但不宣称主机独占或生产 P95。计时覆盖范围准备、评分／选择、范围核验、实际重算、聚合和候选临时对象释放；加载、metadata、查询嵌入、oracle 与质量核验另列。每进程 10 分钟超时，只清理自有进程组。

逐次检查候选距离 bits 和排序身份、重复稳定性、范围一致、预算上限、短结果及最佳片段。oracle 矩阵在正式请求前读入并检查有限性，包含在整个 harness 的内存观测中；execute 不引用它，所有距离核验及质量计算在该次计时返回后进行。质量只统计第一轮每个查询；私有第二轮行复用第一轮缓存指标，公开统计显式标注 quality_source_repeat=0。固定预算间的失败、同分宽容指标与严格指标均保留，不用最终成功预算掩盖较小预算的失败。输出公开查询序号／语言／类别和统计，不输出私有语料、路径、来源身份或端点。

先写一个可运行行为自检观察失败，再实现可变预算入口；复用既有边界自检，额外验证小预算漏掉对象最佳片段而较大预算恢复的反例。运行自检、Ruff、Prettier、统计与脱敏检查。结束更新交接入口。生产代码、schema、依赖、真实库、用户已有改动、分支与提交均保持原状态。
