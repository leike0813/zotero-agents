### F1 [P1][性能] packages/synthesis-contracts/src/durableBundle.ts:641 —— 分组用数组展开插入，单项上限 25 万时退化为 O(n²)

- 证据：
```ts
    for (const entry of entries) {
      const path = bundlePathFor(entry);
      groups.set(path, [...(groups.get(path) ?? []), entry]);
    }
```
- 分析：每插入一个 entry 都把该分组已有全部元素复制一遍，单组 k 个元素的总拷贝量是 k(k+1)/2。本文件自身声明的每类上限（第 51-77 行）为 `concept_alias/concept_relation = 250_000`、`concept_sense = 100_000`、`concept = 25_000`，而这些实体各自只落在同一个 `bundles/<kind>.json` 分组里（`bundlePathFor`，529-533 行），因此 25 万别名会产生约 3.1×10¹⁰ 次元素拷贝。`buildExport` 是 WebDAV 同步的导出路径（`SynthesisWebDavSyncDurablePort.buildExport`），一旦库变大即表现为长时间卡死/内存暴涨。附带成本：`bundlePathFor(entry)` 对每条 entry 都执行一次（topics 分支内部还要 `hashCanonicalJson`）。
- 建议：改成原地追加——`const group = groups.get(path); if (group) group.push(entry); else groups.set(path, [entry]);`；`bundlePathFor` 结果可按 entity 缓存。
- 置信度：高（复杂度确定；触发规模取决于真实库大小）
