### F1 [P2][正确性] skills_src/topic-synthesis/runtime/topic_synthesis_runtime/common/topic_synthesis_db.py:3457 —— 每个主题产物都被硬编码为 "computer vision" 学科
- 证据：`"discipline": "computer vision",` / `"research_area": title,`

- 建议：从 topic context/planned topic 读取学科字段，缺失时置空并把校验下沉为显式错误，而不是填默认值。
- 置信度：高（硬编码确凿；下游影响面按 artifact section 计）

### F7 [P3][边界] read.rs:335 —— metrics 分页的 cursor 加法可整数溢出
- 证据：`let next = request.cursor + page.records.len();`
- 分析：`request.cursor` 来自客户端 DTO（未做上界校验，`metrics()` 只校验 limit 与 paper_refs 数量），`cursor` 为 `usize`。传入接近 `usize::MAX` 的 cursor 时，debug 构建 panic，release 构建静默回绕，使 `next < page.total` 可能成立并返回一个异常小的 `next_cursor`，向客户端暴露错误的分页位置（并把该值转交 repository 作为 offset）。
- 建议：用 `checked_add` 并对超大 cursor 直接返回 `invalid_request`。
- 置信度：中（溢出行确凿；可达性取决于 capability 是否接受任意 usize cursor）

### F9 [P3][契约/性能] topic_synthesis_db.py:574 —— `hash_value` 计算后无人消费，artifact 注册表是进程内全局字典
- 证据：`ARTIFACT_PATHS[key] = path\n    return None` 与 `path = ARTIFACT_PATHS.get(key)\n    if not path:\n        return None\n    return {"path": path}`
- 分析：`write_json`/`write_text` 对每个产物做完整 SHA-256 并 `return sha256_file(path)`，调用方全部把它作为 `hash_value` 传进 `register_artifact`，而该函数只把 `path` 写进模块级 `ARTIFACT_PATHS` 后返回 `None`——哈希从不落库也不进 handoff/manifest，等于对每个 section/sidecar/view 白算一次全文件摘要且无法做完整性校验。同时 `artifact_entry` 忽略传入的 `conn` 而读全局 dict，意味着同一进程内多次运行会互相覆盖路径（gate 为一次性进程，暂未触发，但语义上 registry 不在 DB 里）。
- 建议：把 hash 持久化到 stage_state/metadata 或直接删除哈希计算；registry 改为按运行读取 DB 行。
- 置信度：高（丢弃证据确凿）；跨进程影响为判断

### F10 [P3][契约] gate.py:95 —— `--action cancel` 只打印，不写 DB/result，与 payload 取消路径不一致
- 证据：`canceled = {\n                "__SKILL_DONE__": True,\n                "kind": "topic_synthesis_canceled",`（gate.py 内联构造后 `_print_json`，没有 `connect`/`write_canceled_output`）对比 `write_json(run_root / "result/topic-synthesis-canceled.json", canceled)\n    set_meta(conn, "canceled_output", canceled)`
- 分析：DB 模块的取消语义是「写 `result/topic-synthesis-canceled.json` + `set_meta(canceled_output)`」，而 `current_stage` 正是靠 `get_meta(conn, "canceled_output")` 返回 `None` 才算终止（595-596 行）。CLI 取消路径两者都不做，因此 1) 取消不会留下任何持久化证据；2) 同一 DB 上再次 `--action gate/run` 仍会返回待办 stage，取消可能被静默忽略；3) 取消 payload 的形状被复制到两处，字段易漂移（CLI 版本无 `retryable`）。
- 建议：让 gate.py 的 cancel 走 `write_canceled_output`（复用同一 shape），或明确取消为纯输出并移除 DB 侧的 canceled 判定分支。
- 置信度：中（无持久化确凿；是否会被再次 gate 取决于编排器，属判断）
