### F1 [P2][信任边界] src/modules/workflowExecution/bundleIO.ts:21 —— provider 返回的 requestId 未净化即拼入临时文件名，存在路径穿越/覆盖风险
- 证据：
  ```ts
  return joinPath(tempDir, `zotero-skills-${requestId}-${stamp}.zip`);
  ```
  调用侧：`openRunResultBundleReader({ result, requestId: result.requestId })`（applySeam.ts:724-727），`result.requestId` 直接来自 provider 结果；同文件 `createDirectoryBundleReader` 走的是 `normalizeEntryPath`（剔除 `..`），临时路径这条路径没有等价处理。
- 分析：触发条件是后端返回的 `requestId` 含 `/`、`\` 或 `..`（例如 `..\..\some.zip`）。`writeBytes` 用 `{overwrite:true}` 写该路径，随后 `dispose` 还会 `removeRuntimePath` 同一路径，因此最坏情况是在临时目录之外创建/覆盖/删除文件。该字符串跨网络信任边界（backend → 本地文件系统），而本文件其它入口都对路径做了归一化，属遗漏而非有意设计。
- 建议：对 requestId 做白名单化（如 `replace(/[^A-Za-z0-9._-]/g, "_")` 并限制长度）后再拼文件名，保留 stamp 作为唯一性来源。
- 置信度：中（依赖 `utils/path.joinPath` 不再做 `..` 归一化；若 joinPath 已归一化则降级为健壮性问题）

### F3 [P3][并发/资源] src/modules/workflowExecution/applySeam.ts:915 —— finally 内先 await dispose，抛错会跳过后续资源释放并覆盖主错误


- 分析：`dispose()` → `removeRuntimePath`（Windows 上文件被占用/权限问题会抛错）。一旦第一个 dispose 抛出，`sequenceBundleResources` 中已打开的 temp zip（每个 sequence step 一个）全部泄漏，且 `finally` 抛出的新错误会替换 try 块的原始业务错误（apply 的真实失败原因），调用方只能看到清理错误。

- 置信度：中
