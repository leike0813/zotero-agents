### F1 [P1][信任边界] assets/skillrunner-output-contract/skill_runner_contract/artifact.py:75 —— 越出 run dir 的（含绝对）工件路径被 `shutil.move` 搬入 run dir 并随后打进 bundle

- 证据：
  ```
        resolved = source_path.resolve()
        if not _is_relative_to(resolved, root):
            target = run_dir / "artifacts" / field.name / resolved.name
            shutil.move(str(resolved), str(target))
  ```
  配合 `_resolve_run_local_path`（第 241-242 行）：
  ```
    if candidate.is_absolute():
        return candidate.resolve()
  ```
- 分析：相对路径被严格拒收（含 `""/"."/".."` 直接 `ValueError`），但**绝对路径完全绕过校验**并直接 `resolve()`；当它不在 run dir 内时，第 79 行用 `shutil.move`（跨设备为 copy+unlink，同设备为 rename）把宿主文件搬进 run dir，随后 `artifacts` 进入 `result.json` 与 zip bundle（`bundle._artifact_candidates_from_result` 只校验“在 run dir 内”，此时已成立）。触发条件：skill 输出的 payload 里，把某个 `x-type: artifact|file` 字段写成宿主绝对路径（如 `~/.zotero/zotero.sqlite`），或在工作区里放一个指向宿主文件的符号链接再填该链接名（`.resolve()` 会跟随符号链接）。影响：任意宿主文件被读取/外泄（用户下载 bundle 即返回给调用方），且原文件被**删除/移动**，属不可逆数据破坏。对称性证据表明这不是有意为之：同一函数对相对路径做了严格拒绝。
- 建议：最小修复——仅接受 run dir 内路径（否则记为 `missing/invalid` 并拒绝），确需支持外部作品目录时改用 `shutil.copy2` 且限定允许的来源根；对 `source_path.is_symlink()` 单独处理。
- 置信度：高（代码路径明确；威胁模型取决于 payload 信任级别，按 SkillRunner 由 agent 产出 payload 视为不可信）

### F10 [P2][信任边界] addon/content/shared/markdown-renderer.js:292 —— 消毒器把 data:image 白名单复用到 `href`，且未覆盖 `xlink:href`

- 证据（第 245-254 行服务函数与第 292-299 行使用处）：
  ```
      if (ALLOWED_DATA_IMAGE.test(value)) {
        return value;
      }
  ```
  ```
          if (name === "href" || name === "src") {
            const resolved = safeResolvedUrl(value, options);
  ```
  其中 `ALLOWED_DATA_IMAGE = /^data:image\/(?:png|jpe?g|gif|webp|svg\+xml);/i`（第 53 行）。
- 分析：(a) 该正则包含 `svg+xml`，对 `<img src>` 是安全的（SVG 在 img 中不执行脚本），但对 `href` 语义不同——`<a href="data:image/svg+xml,<svg onload=...>">` 会在 `html:true` 的 profile（document/synthesis/standaloneDigest）下原样保留并被 `bindLocalAnchors` 补上 `target=_blank`；这里比 markdown-it 自身的链接白名单（仅 png/jpeg/gif/webp，且拒绝 `data:` 链接）更宽松，说明是本文件引入的放宽。(b) 属性名按 `attr.name.toLowerCase()` 比较，SVG 外来属性在 DOM 中是 `xlink:href`（`name !== "href"`），因此 `<svg><a xlink:href="javascript:...">` 完全不经过协议白名单。触发条件：渲染来源含未净化 HTML 的 markdown（agent 产出/摘要在 `synthesis`/`document` profile）。影响面取决于宿主浏览器对 `data:` 文档导航与 SVG 锚点 javascript: 的策略（Zotero 为 Firefox 内核、内容位于受信任 iframe），故不判为已证实的可利用 XSS。
- 建议：data: 白名单只用于 `src`（`href` 一律走 `ALLOWED_PROTOCOLS`）；属性判定改用 `attr.localName`（或先剥 `xlink:` 前缀），并把 `svg/math` 内部用到的命名空间属性显式纳入。
- 置信度：低（代码路径确凿，浏览器级可利用性未证实）
