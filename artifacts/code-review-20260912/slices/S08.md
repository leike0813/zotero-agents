### F2 [P2][错误处理] src/modules/bufferedWriteCoordinator.ts:136 —— sink 持久化失败只累加诊断后被吞掉，且失败后不再安排任何重试
- 证据：
```ts

    state.timer = null;
    void drain(state).catch(() => undefined);
  }, BUFFERED_WRITE_DELAY_MS);
```

- 分析：`drain` 失败时在 172-179 恢复 `pending`、置 `failed = true` 并 rethrow；`.catch(() => undefined)`（以及 276 行同样的吞错）使异常在定时器路径彻底消失，finally 里的 `!state.failed` 判断又阻止了重新 schedule。于是：sink 瞬时失败 + 之后没有新的 enqueue（或新 enqueue 未达 256 条/128KiB 阈值）时，数据长期停留在内存中，只能等显式 `flushBufferedWrite*`；生产环境没有任何日志/告警，`failures` 只在 `getBufferedWriteDiagnosticsForTests` 里可见。另外 `flushAllBufferedWrites` 用 `Promise.all`，任一 key 失败会掩盖其它 key 的 flush 结果。
- 建议：为 sink 失败提供诊断回调/日志并安排一次（退避的）重试定时器；聚合 flush 改用 `allSettled` 并回传失败 key。
