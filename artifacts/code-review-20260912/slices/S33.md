- 分析：`createNativeSynthesisClientComposition` 在构造时自行 `createSynthesisSidecarRpcClient({...})`（第 637-641 行），而 `dispose()` 只置 `active=false`，没有任何 `close/dispose/abort` 调用。`NativeRpcClient` 被定义为 `Pick<ReturnType<typeof createSynthesisSidecarRpcClient>, "call">`，说明真实对象有 `call` 之外的成员（很可能是连接管理/agent/定时器）。`defaultClient` 每次 `getFreshDefaultSynthesisClient()` / `invalidateDefaultSynthesisClient()` 都会新建一个组合，因此每代都会留下一个未被释放的客户端；在扩展长期运行的场景下这是按代累积的句柄泄漏。
