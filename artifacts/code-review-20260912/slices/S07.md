### F1 [P2][并发/资源] src/modules/guardedSqlite.ts:145 —— PRAGMA 配置失败后 ownerCount 已被 +1，连接永久无法关闭
- 证据：
```
143	    entriesByPath.set(key, entry);
144	  }
145	  entry.ownerCount += 1;
146	  configureBusyTimeout(entry);
```
- 分析：`configureBusyTimeout` 内部走 `withBusyRetry`，非 busy 错误或 3 次 busy 用尽都会抛出。此时 entry 已在 `entriesByPath` 中且 `ownerCount` 已自增，但调用方拿不到句柄，永远不会有配对的 `release()`。触发条件：`PRAGMA busy_timeout` 执行失败（例如初始化期另一个连接持锁）。影响：ownerCount 永不归零 → `PRAGMA wal_checkpoint(TRUNCATE)` 与 `asyncClose()` 永不执行，DB 句柄与 WAL 泄漏至进程结束；且因 `busyTimeoutConfigured` 仍为 false，每次后续 acquire 都会重复失败/重试。
- 建议：把 `entry.ownerCount += 1` 放到 `configureBusyTimeout` 成功之后；或在 catch 中回滚（ownerCount 自减 + 必要时从 map 移除）后再抛出。
- 置信度：高

### F2 [P2][信任边界/正确性] src/modules/zoteroHostMutationAuthority.ts:207 —— 内存键以 `\n` 拼接，且 started 分支不复验 digest，跨 operation 结果可互串
- 证据：
```

208	  return `${scope}\n${operationId}`;
209	}
```

- 分析：`requireScope` 只校验非空且 ≤256，`requireOperationId` 只 trim + 长度 ≤128，两者都未禁止 `\n`，也未转义。于是 `(scope="a", op="b\nc")` 与 `(scope="a\nb", op="c")` 生成同一个内存键。durable 路径有 `assertEntryBinding`，但 started 分支只按键取内存记录、不比对 `live.digest`/scope，所以后者会拿到前者的执行 promise 与其终态结果（wrong-owner result）。触发条件：调用方把含换行的 operationId 与特定 scope 组合传入（operationId 来自调用侧、未经字符集限制）。

- 置信度：中
