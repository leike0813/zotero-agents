### F1 [P2][正确性/静默数据丢失] rust/synthesis-sidecar/crates/synthesis-application/src/tag_vocabulary.rs:772 —— 公开 staged 变更路径按小写建表，会把大小写不同的兄弟 staged 行（及其 parent bindings）静默删除
- 证据：
```
        let mut by_lower = current
            .iter()
            .cloned()
            .map(|entry| (entry.tag.to_lowercase(), entry))
            .collect::<HashMap<_, _>>();
...
        let mut replacement = by_lower.into_values().collect::<Vec<_>>();
```
- 分析：`staged` 表允许存在仅大小写不同的行（内部 `stage`/`replace_staged` 只拒绝**完全相等**的 tag，见 1567-1576；测试 `promotes_case_variant_staged_rows_as_one_canonical_tag` 正是把 `method:CNN` 与 `method:cnn` 同时写入）。当 store 中存在这种行、而用户经公开路径（Tag 面板）再 stage 同一小写键时：`collect::<HashMap<_,_>>` 只保留迭代中最后一个 `by_lower[tag.to_lowercase()]`，`into_values()` 写回的 replacement 少一行 → 被覆盖那行的 `note/source/facet` 与独有 bindings 永久丢失（`merge_staged_record` 只合并存活行的 bindings）。同一入口内若一次提交两个大小写变体，`written` 会返回 2 条而 DB 只有 1 条，返回值与持久状态不一致。`update_public_staged` 同源问题：`current.retain(|entry| { let key = entry.tag.to_lowercase(); key != original && key != requested })`（819-822）会一次性删掉两个小写键下的**所有**行，只重建合并后的一行，原行 bindings 同样丢失。
- 建议：把“按小写归并”限定到同一 key 的候选集合而非整表——即保留未命中该小写键的行、只对命中行做 winner 合并；或让 `by_lower` 存 `Vec<Record>` 并在写回前保留非选中行。
- 置信度：中（机制确定，触发需 store 中已存在大小写变体）

- 分析：`prepare_refresh_with_options` 只在入口处（376-387）检查 `accepting` 并置 `state.active = true`，随后长时间做仓储 IO（`snapshot_for_prepare` / `upsert_operation`），最后才在 572-574 安装 preparation。若 `stop_admission()` 在该窗口内执行，它看到的 `state.preparation` 仍是 `None`，于是既不取消任何东西、也不会阻止随后被安装的 preparation；`shutdown()` 因 `wait_timeout_while(state.active)` 在 prepare 结束时正常返回 Ok（调用方认为已 drain）。后果：(a) 操作记录 `operation:{id}` 永远停留 `running`（`finish_operation` 无人调用）；(b) 调用方仍持有 `Prepared` + preparation_id，而 `apply_refresh_with_commit`（620-648）只校验 `state.preparation`/id、**不校验 `state.accepting`**，因此可在 stop/drain 之后继续写 `replace_reference_projection`。

### F5 [P3][契约/信任边界] rust/synthesis-sidecar/crates/synthesis-application/src/canonical_literature_artifacts.rs:311 —— `deny_unknown_fields` 与 `flatten` 组合在 serde 中不受支持，unresolved mention 的未知字段实际不会被拒绝
- 证据：
```
#[derive(Clone, Debug, Deserialize)]
#[serde(rename_all = "snake_case", deny_unknown_fields)]
pub struct CitationUnresolvedMention {
    #[serde(flatten)]
    pub mention: CitationMention,
    pub reason: Option<String>,
}
```
- 分析：serde 文档明确 `deny_unknown_fields` 不能与 `flatten` 同时使用（不报错但失效）：外层结构在 flatten 路径上把未匹配键交给 `FlatMapDeserializer`，不会再做 unknown-field 判定，内层 `CitationMention` 的 `deny_unknown_fields` 同样失去意义。而本文件头声明“mirror that closed wire shape so the native application can reject aliases and storage wrappers before projection”，且测试 `rejects_aliases_and_unknown_source_ids` 只覆盖了非 flatten 的结构。结果是 citation artifact 的 `unresolved[].*` 可携带任意别名/包装字段直通投影（`roles_for_reference` 用它生成 roles）。
- 建议：去掉外层 `deny_unknown_fields`（接受放行并显式记录），或把 `CitationMention` 的字段直接内联进 `CitationUnresolvedMention`（不用 flatten）以恢复严格拒绝。
- 置信度：中

### F7 [P3][并发] rust/synthesis-sidecar/crates/synthesis-application/src/reference_refresh.rs:773 —— `stop_admission` 在持有 `state` 互斥量期间执行仓储写（`finish_operation`），与 `discard_preparation`/`end_run` 的“锁外收尾”不一致
