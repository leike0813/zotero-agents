## B. Findings

### F1 [P2][正确性] rust/synthesis-sidecar/crates/synthesis-sidecar/src/runtime_production_ports.rs:564 —— `source_structure_version` 由 ISO 字符串 parse 成 i64，恒为 0（静默）
- 证据：`:430` `let updated_at = utc_now_iso8601();`；`:564` `let source_structure_version = updated_at.parse::<i64>().unwrap_or_default();`；`:691` `source_structure_version: updated_at.parse().unwrap_or_default(),`
- 分析：`utc_now_iso8601()` 产出 ISO-8601 文本（同 crate 用 `synthesis_protocol::unix_millis_from_utc_iso8601` 反解它，见 `runtime_production_ports.rs:2070`、`:2118`），`parse::<i64>()` 必然 Err，`unwrap_or_default()` 把失败吞成 0。结果是 `CitationLightMetricsRecord` 与 `CitationComplexMetricsRecord` 的 `source_structure_version` 全表同值 0；任何以该列做 basis/陈旧判定的读路径都会永远判为“未变”。触发条件：任意一次 citation graph build/metrics 落库即可。
- 建议：改用 `current_time_ms()` 写入数值版本，或保留字符串并显式转换；至少不要用 `unwrap_or_default()` 掩盖非法时间戳。
- 置信度：中（依赖 `utc_now_iso8601` 确为 ISO 文本，由同文件反解函数佐证）

### F2 [P2][信任边界] rust/synthesis-sidecar/crates/synthesis-sidecar/src/runtime_topic_workbench_surface.rs:449 —— review 页 `limit` 客户端可控且无上界，直接进入仓储查询

- 分析：`review_page_query` 被 `topic_graph_review` / `concept_review` 使用，`limit` 原样进入 `ReviewPageQuery`，无任何上限（同文件 `decode_resolver` 在 1352-1354 明确 `limit == 0 || limit > 250` 拒绝，`review_bound` 也设上限）。客户端传 `limit=10^12` 可要求一次全表/巨量分页，配合 `usize` 强转在大 offset 上还会截断。

### F7 [P2][错误处理] rust/synthesis-sidecar/crates/synthesis-sidecar/src/runtime_production_client.rs:982 —— 已提交的变更在超时后仍以错误码返回
- 证据：
```
    if started_at.elapsed() > Duration::from_millis(metadata.deadline_ms) {
        return Err("operation_timeout".into());
    }
```
- 分析：该判定位于 handler 已执行、`:969-973` `canonical_autosync.observe_commit(...)` 与 `:976-981` `record_semantic_mutation_result(...)` 之后。因此“durable 已提交 + 诊断记为 succeeded”与返回给 Host 的 408 互相矛盾：Host 可能据此重试/进入 repair，而状态已变更（`production_client_error_status` 把 `_timeout` 映射为 408，语义上鼓励重试）。

### F8 [P3][并发] rust/synthesis-sidecar/crates/synthesis-sidecar/src/runtime_production_client.rs:886 —— 在整个 content-transfer 读+哈希期间持有 transfer 全局锁
- 证据：
```
        runtime
            .transfer
            .lock()
            .map_err(|_| "transfer_unavailable".to_owned())?
            .production_client_request(&transfer_control.request_transfer.session_id, capability)?
```
- 分析：`NativeTransferOwner::production_client_request`（runtime_transfer.rs:1306-1363）会逐页 `read_value` 并对拼接文本做 `canonical_sha256`，上限 `MAX_DIRECTION_BYTES = 1GB`；这些文件 IO 与哈希全在 `Arc<Mutex<NativeTransferOwner>>` 内完成，期间所有其它 transfer 动作（begin/put/seal/execute/get_output_page/cancel，含 delivery 回调路径）全部阻塞。
- 建议：先在校验/快照阶段把需要的页读成内存或句柄，再进锁做状态判定；或把 content 读取移出 owner 锁的范围。
- 置信度：中

### F9 [P3][契约] rust/synthesis-sidecar/crates/synthesis-sidecar/src/runtime_production_ports.rs:921 —— tag 索引构建丢弃 aliases/abbrev，与 validate 的请求形状不对称

                "entries":tag_worker_entries(entries)?,
