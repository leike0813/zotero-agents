### F1 [P2][正确性] src/synthesis/components/reviewCenter/ReviewCenterRegion.tsx:1300 —— 本地对账 effect 的“批处理完成”分支不可达，localPending/localSubmission/selectedIds 永不清理
- 证据：
```
      : completedReferenceBatch && submittedReferenceIds.size
        ? null
        : localSubmission;
```
```
  if (submission) {
    if (completedKey === REFERENCE_BATCH_OPERATION_KEY) {
```
（派生 `submission` 见 :1237-1243；effect 见 :1300-1301）
- 分析：进入 `completedKey === REFERENCE_BATCH_OPERATION_KEY` 分支要求 `submission` 为真，而 `submission` 为真又要求“`completedReferenceBatch` 为假 或 `submittedReferenceIds` 为空”。`applyPending`(:1445) 提交时总是把 ref 设为非空，且全程无人清空 ref，故批次完成时 `submission` 必为 `null`，清理分支与失败分支 `setSubmission(null)` 永不执行。触发路径（调用方未传 `referenceReview` 时）：一次成功 apply 后，任何其它 host 动作完成都会把 `actionEcho.completedKey` 换成别的键 → `completedReferenceBatch` 假 → 派生 `submission` 回到陈旧的 `localSubmission`，派生 `pending` 回到未清理的 `localPending`：已提交的决策重新显示为 pending，`isSubmitting()` 恒真导致 apply 按钮永久禁用并显示 “applying pending”，`selectedIds` 也不清空。
- 建议：按 actionEcho 的批次键直接判定清理（不要以派生 `submission` 作闸门），并在完成/失败后清空 `submittedReferenceIdsRef`。
- 置信度：高（逻辑不可达性可静态确定；生产可达性取决于是否始终注入 `referenceReview`）

### F2 [P2][正确性] src/synthesis/components/reviewCenter/ReviewCenterRegion.tsx:1217 —— `submittedReferenceIdsRef` 只写不清，同一提案的后续决策被静默丢弃

- 分析：批次完成后 ref 永久保留已提交 id，派生 `pending` 会持续把这些 id 从 `localPending` 中滤掉。用户对同一提案再下决策（典型：批处理后该行变为 accepted，再点 “reopen”）时 `queueDecision` 写进 `localPending`，但 `pending.get(proposalId)` 为空 → 状态列无 pending 徽标、`pendingCount` 不计数；`applyPending` 用 `pending.values()` 构造 decisions(:1435)，该决策永远不会被提交，用户在 UI 上也无从发现（与 F1 同源）。

### F4 [P3][正确性] src/synthesis/components/registry/registryTypes.ts:346 —— `finiteNumber` 把 null/""/false 当作 0，缺省值被渲染成 0 而非 unknown
- 证据：
```
function finiteNumber(value: unknown): number | undefined {
  const parsed = Number(value);
  return Number.isFinite(parsed) ? parsed : undefined;
}
```
- 分析：`Number(null) === 0`、`Number("") === 0`、`Number(false) === 0`，因此 wire 中 `null`（Rust `Option::None` 序列化）或空串会得到 0 而非 `undefined`：`narrowRegistryRow:601` 的 `ratingScore` 变 0 → `RegistryTables.tsx:101-113` 的 missing 分支（`synthesis-rating-unavailable`）永不触发，显示“0 星”而不是“不可用”；`narrowCanonicalRow:695` 的 `rawReferenceCount` 变 0 → `CanonicalRevisionWorkbench.tsx:1171-1175` 的 `=== undefined ? "-" : …` 显示 "0" 而非 "-"。
- 建议：先判断 `value == null || value === "" || value === false` 返回 undefined，再做 `Number`。
- 置信度：中（取决于宿主是否以 null/"" 表达缺省；类型上 `ratingScore?: number` 的“不可用”分支说明缺省是预期状态）
