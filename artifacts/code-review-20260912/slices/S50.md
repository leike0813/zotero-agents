### F1 [P2][正确性] src/modules/hostBridge/workflow/hostBridgeWorkflowResources.ts:681 —— 不同输出 slot 同名同序号时分配到同一物理文件，且路径索引被覆盖

- 证据：
```ts

...
const path = joinPath(outputRoot, numberedName(suggestedName, ordinal));
...
allocationByPath.set(path, allocationId);
```
- 分析：`allocationCountBySlot` 是 **按 slot** 计数的，而路径只由 `outputRoot + suggestedName + ordinal` 决定。当两个输出 slot 使用同一 `suggestedName`（或都回落到 `"output.bin"`，见 667-669 行）时，两者的 ordinal 都是 1，得到同一路径：`allocationByPath` 被后者覆盖；随后 `publishOutput` 里 `allocationByPath.delete(allocation.path)`（782 行）会删掉另一条 allocation 的路径索引，使按路径（不带 allocationId）发布的那一路直接报 `workflow_resource_output_invalid`。更严重的是两个 slot 指向同一文件：先发布并 `registerHostBridgeWorkflowArtifactFile` 的产物会在后一个 slot 写入被覆盖后内容改变，而已登记 descriptor 的 sha256/size 仍是旧值，下载端拿到的是别的内容（内容与摘要不一致）。
- 建议：分配路径时把 slot 纳入命名空间（如 `safeName(slotId)` 子目录），或全局唯一序号；`publishOutput` 删除索引前校验 `allocationByPath.get(path) === allocationId`。
- 置信度：中

### F8 [P3][并发] src/modules/skillRunner/connection/skillRunnerConnectionGovernor.ts:891 —— 超时回调内先记债并驱逐，可能把自身驱逐成 evict，导致债务不释放且错误类型变为 abort

- 证据：
```ts

entry.controller?.abort();
finishReject(timeoutError, "timeout");
```
- 分析：`recordPhysicalDebt` 内部调用 `evictDegradedWarmStreams(entry.backendId)`（685 行）。记债后 `maxForegroundStreams` 降为 1，若该后端此时有 ≥2 条 active foreground-stream，循环会按 `pickLeastRecentlyFocusedStream` 驱逐，被驱逐者可能就是**当前这条刚超时的 entry**：`abortForegroundStreamEntry` 会对它执行 `reject(abortError)` + `finish(entry,"evict")`（770-794 行）。随后 `finishReject(timeoutError,"timeout")` 只能走 `recordLateSettlement`，因 `finishReason === "evict"` 既不 `releasePhysicalDebt`（该分支只在 `timeout` 下释放），也不产生 timeout 审计，调用方拿到的是 `AbortError` 而非 `SkillRunnerConnectionTimeoutError`。即：一次超时被记录成 abort，物理债务只能等 30s cooldown 自然过期。
- 建议：回调顺序改为「先 abort/finish 超时条目，再 recordPhysicalDebt」，或在 `recordPhysicalDebt` 的驱逐集合中排除当前 entry。
- 置信度：中

### 存疑（未作为 finding，供主代理复核）

- **权限决策是否被校验**：`submitHostBridgeWorkflow`（2079-2083）与 `applyHostBridgeWorkflowAgentRun`（1791-1806）拿到 `HostBridgePermissionDecision` 后直接进入写路径，代码中从未检查 `outcome`；而 `scopedCancelDecision`（3452-3456）显式构造 `outcome: "approved"`，说明该字段存在非 approved 取值。若 `requestHostBridgePermissionForRequirement` 是「返回拒绝决策」而非抛错，则提交/回写会在未审批时继续。本切片不含 `hostBridgePermissionManager`，无法确证，故不计为缺陷。
