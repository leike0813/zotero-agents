## B. Findings

### F1 [P2][资源] src/sidebar/assistantWorkspaceAcpChild.js:1857 —— regionCollapse observer 永不释放
- 证据：`createRegionCollapseController({ root: elements.root, regions: { toolbar: ..., banner: ..., composer: ... } })` 持有 `ResizeObserver`（assistantRegionCollapse.ts:239 提供 `dispose()`），但 child runtime 没有任何 `regionCollapse.dispose()` 调用（grep 整 slice 唯一 `regionCollapse.refreshLabels()` 在 1819 行）。
- 分析：单 iframe 生命周期内随页面卸载消失，所以「绝对泄漏」不成立；但 `assistantPanelRenderer.js` 的根元素被替换（prototype harness 切 lane 时 `renderMockPane` 第 2421 行 `mount.innerHTML = ""`）会让 `ResizeObserver` 仍 hold 旧 root 引用，直到 controller `dispose()`。
- 建议：在 child runtime 暴露 `dispose` 钩子，host 在 `handleFrameLoad` 或 `clearChildPayloadState` 时显式调用；或让 controller 订阅 root `isConnected` 自动 disconnect。
- 置信度：中

### F2 [P2][契约/一致性] src/sidebar/assistantTranscriptRenderer.js:2491 —— `applyAssistantTranscriptEffects` 静默吞掉 `failure` 信息
- 证据：`function applyAssistantTranscriptEffects(options) { return applyAssistantTranscriptEffectsExact(options).ok; }`。`Exact` 在 2361 行显式构造 `failure: { stage, code }`，wrapper 只回传布尔。
- 分析：`assistantWorkspaceAcpChild.js` 同时 import `applyAssistantTranscriptEffects` 与 `applyAssistantTranscriptEffectsExact`；新 `renderMutationEffect` 走 Exact 拿到完整 failure 并交给 `ack(..., failure)`。旧 wrapper 若被任何残留或第三方消费者调用，失败只能拿到 `false`，无法区分 `node-map-missing` / `page-invalid` / `virtual-reconcile-failed`。契约 §2 要求「失败原因可观测」。
- 建议：给 wrapper 加 `@deprecated` 注释指向 Exact 版本；或把 `failure` 加入返回值。
- 置信度：高

### F3 [P2][资源] src/sidebar/assistantTranscriptRenderer.js:901 —— `requestVirtualTranscriptPage` 的 5s loadingCursors 清理 setTimeout 不取消
- 证据：`state.loadingCursors.add(cursorKey); ... options.onRequestPage(...); setTimeout(function () { if (state.ownerKey === requestedOwnerKey && state.loadingCursors === requestedLoadingCursors) { state.loadingCursors.delete(cursorKey); } }, 5000);`
- 分析：每次调用都创建 5s setTimeout 但从不 cancel，也不在 owner 切换时主动取消（仅靠 ownerKey+loadingCursors 引用对比兜底）。常态不可达（页面会到达或 owner 切换清理），但 `applyAssistantTranscriptEffectsExact` 的 `pageRejected` 分支会再走 `requestVirtualTranscriptPage`，后端持续给坏 page 时闭包引用累积。
- 建议：把 setTimeout id 存到 `state.requestTimers: Set<number>`，`resetVirtualTranscriptState` 时 `clearTimeout`；或在 owner 变更时主动清场。
- 置信度：中

### F4 [P3][可维护性] src/sidebar/assistantTranscriptRenderer.js:2125 —— `transcriptItemSignature` 字段集合与 row 实际显示字段不一致
- 证据：`transcriptItemSignature`（行 2125）拼入 `source.toolKind / inputSummary / resultSummary / summary / createdAt / updatedAt / revision.* / items[]`，但 `renderPresentationRow`（行 1862）渲染时还会消费 `item.level`（行 1783-1789 派生 `level-warn/level-error` class）以及 workspace-activity 路径下的 `item.details.relativePath`（行 2015）。这些未进入 signature。
- 分析：若后端在同 rowKey 上把 `level` 从空改 `"warn"`，signature 不变 → 行不重渲染 → CSS class 不更新。可达性取决于后端是否独立发 patch 不带 revision bump。
- 建议：把 `level`、`details.relativePath`、workspace-activity 标志加入 signature；或对全 `item` JSON 序列化。
- 置信度：低

### F5 [P3][可观测性] src/sidebar/assistantTranscriptRenderer.js:2168 —— streaming 行回退路径与 full re-render 顺序抖动
- 证据：`if (suffix && textNode && textNode === body.lastChild && typeof textNode.appendData === "function") textNode.appendData(suffix); else if (suffix) body.textContent = nextText;` 之后紧跟 `renderAssistantTranscriptItem(row, item, options)` 行 2202 重新跑。
- 分析：`body.textContent = nextText` 在 full re-render 之前先把已渲染的 markdown body 清掉，然后又被 full re-render 重建。属 transient 抖动而非真实缺陷，但代码可读性差。
- 建议：把 `body.textContent = nextText` 替换为直接调用 `renderAssistantTranscriptItem(row, item, options)`。
- 置信度：低

### F6 [P2][契约/一致性] src/sidebar/assistantWorkspaceAcpChild.js:1755 —— expandedTranscriptRows 跨 owner 不清场
- 证据：`ui.expandedTranscriptRows: new Set()`（行 1222）初始化后，`renderMutationEffect`（行 1640）直接传给 `applyAssistantTranscriptEffectsExact`；`applyOwnerNavigationUiTransition`（行 1077）只重置 `replyDraft / contextDrawerOpen / detailsDrawerOpen / permissionRequestOpen`，未触碰 `expandedTranscriptRows`。
- 分析：用户折叠一组 tool activity 切换 conversation，新 conversation 的 rowKey 集合完全不同，`expandedTranscriptRows` 仍持有旧 owner 的 rowKey，无可见影响（key 不命中）但 Set 无限增长。违反 §2 「折叠状态只允许切 class/属性，不得进入 signature 或 panel DTO」—— 这里 expandedIds 间接进入 transcript signature（`transcriptItemSignature` 行 2136 `expanded` 字段），且跨 owner 不清场。
- 建议：在 `applyOwnerNavigationUiTransition` 里 `ui.expandedTranscriptRows.clear()`；或把 `transcriptItemSignature` 的 `expanded` 字段改为按 ownerKey 分桶的 Set。
- 置信度：中

### F7 [P3][契约/一致性] src/sidebar/assistantPanelModel.js:1755 —— 抽屉 selectedTaskKey 跨 owner 复用折叠偏好
- 证据：`drawers.selectedTaskKey: safeText(owner && owner.ownerKey)`（行 1755）；`exactWorkspaceDrawerSections`（行 921）`selectedTask` 仅比较 `safeText(selectedOwner.ownerKey)`。`ui.drawerGroupCollapsed: Map<groupKey, boolean>`（行 1224）owner 切换时不清空。
- 分析：跨 owner 复用相同 groupKey 会复用上次折叠偏好。一般 backendId 不同则不冲突，但跨 source（acp-chat ↔ skillrunner）的 groupKey 命名空间可能碰撞。属设计债但代价可控。
- 建议：在 `applyOwnerNavigationUiTransition` 同时 `ui.drawerGroupCollapsed.clear()`；或改 key 为 `source + "\n" + sectionId + "\n" + groupKey`。
- 置信度：低
