### F1 [P2][契约] deterministic_core.py:5266 —— CLI `persist_render_templates` 与 render 前置检查的模板路径契约不一致，导致该路径永远无法 render
- 证据：
```python
_write_text(digest_template_path, normalized_payload["digest_template"])
_write_text(citation_template_path, normalized_payload["citation_analysis_template"])
set_runtime_input(connection, "digest_template_path", str(digest_template_path))
set_runtime_input(connection, "citation_analysis_template_path", str(citation_template_path))
```
- 分析：该 handler 只写入 `digest_template_path` / `citation_analysis_template_path`，而 `_validate_render_prerequisites`（7336-7342）在存在 `persist_render_templates` receipt 时要求四个 key 全部存在：
  `for key in ("digest_template_path", "citation_analysis_template_path", "literature_score_template_path", "scoring_rubric_path") if not inputs.get(key)`。
  触发条件：走 CLI 引导序列（`confirm_runtime_paths` → `bootstrap_runtime_db` → `persist_render_templates` → `normalize_source` → … → `render_and_validate`），render 阶段固定返回 “runtime template paths missing before render: ['literature_score_template_path', 'scoring_rubric_path']”，且 `errors` 非空无法继续。只有 `runtime.persist_default_templates`（runtime.py:132-136）会补齐这四个 key，说明两条模板落盘路径已经漂移。影响：该表面功能不可用（不是仅报错风格问题）。
- 建议：在 `_handle_persist_render_templates` 中同时落盘/登记 `literature_score_template_path` 与 `scoring_rubric_path`（复用 `deterministic_core.TEMPLATES_DIR`/`ASSETS_DIR` 的默认资产），或让 `_validate_render_prerequisites` 对缺失的评分类 key 回退到默认资产而不是硬失败。
- 置信度：中（取决于 CLI 引导路径是否仍在技能文档中对外承诺；代码层面不一致已证实）

### F9 [P3][契约] deterministic_core.py:4869 —— `fix` 模式把缺失的 error 置为 None，随后必被 `_validate_error_obj` 判为非法
- 证据：
```python

```

- 分析：`_materialize_outputs` 用 `candidate.get("error")` 直接赋值；当输入 payload 未携带 `"error"` 时结果为 `None`。`_validate_public_output`（4910）会调用 `_validate_error_obj(None)` 并返回 `["error must be object"]`，于是 `render_and_validate --mode fix` 对任何不含 `error` 对象的输入都以 2 收尾（`fixed["warnings"]` 追加 “still invalid: error must be object”）。触发条件：`--mode fix --in <agent payload>` 且该 payload 无 `error` 键。

- 置信度：中（取决于 fix 输入是否被文档强制携带 `error`）
