### F3 [P2][正确性] skills_builtin/literature-explainer/scripts/dispatch_source.py:170,176 —— PDF 字面量八进制解析用 `isdigit()` 判定，非 0-7 的“数字”字符会让 `int(octal, 8)` 抛错并中止整个兜底
- 证据：
```
        if nxt.isdigit():
            octal = nxt
            step = 2
            while index + step < len(body) and len(octal) < 3 and body[index + step].isdigit():
                octal += body[index + step]
```
（随后 176 行 `chars.append(chr(int(octal, 8)))`）
- 分析：PDF 字面量只允许 `\0-\7` 八进制转义，但 `str.isdigit()` 对 `'8'`/`'9'` 乃至 latin-1 解码出的 `'²' '³' '¹'`（U+00B2/B3/B9）都返回 True。此时 `int(octal, 8)` 抛 `ValueError`，异常沿 `_extract_text_from_pdf_stream` → `_convert_pdf_with_stdlib` 冒到 `dispatch_source` 354 行的 `except Exception`，整份 PDF 直接返回 `CONVERT_FAILED`（exit 2），而不是“该流跳过、其余流继续”。另外 `_convert_pdf_with_stdlib` 对每个 stream 也无逐个 try，一条坏流即终止全部抽取。
- 建议：改为 `if nxt in "01234567"`，并让 `while` 条件同样用 `in "01234567"`；在 `_convert_pdf_with_stdlib` 的 stream 循环内 per-stream try/except，坏流只丢该流。
- 置信度：中（依赖输入中 `\` + 非八进制数字字节，PDF 生成器常见但非必然）。


- 分析：`urllib.request.urlopen` 默认 opener 同时注册 `DataHandler`/`FileHandler`，因此 `source_type="web_url"` + `source="data:text/plain,<任意包含关键词的文本>"` 会成功返回（`getcode()` 为 `None`，代码不校验状态码），随即命中关键词 → `status="pass"`。`file:///...` 同理成为本地文件关键词探测/校验旁路。该工具是 literature-explainer 的证据门禁（`instructions` 里把 pass/fail 作为后续回答的约束），被校验方（模型输出）恰好是输入提供方，等于把门禁交给了被门禁对象。同时也是 SSRF 面（内网/元数据端点可达，尽管正文不外显，仍是盲预言机）。

- 置信度：中高（机制确定；影响取决于该 skill 是否被用作唯一证据门禁）。

### F6 [P3][正确性] skills_builtin/literature-explainer/scripts/memory_engine.py:558 —— 记忆更新为“读全量→截断原文件→重写”，无临时文件/无锁，中断或并发即丢整段记忆

- 分析：`open("w")` 先截断原 JSONL，再逐条写入；进程被中断、磁盘写失败或两次 update 并发交叉时，历史条目会整体丢失或产生半截文件（下次 `_read_jsonl` 直接以 `invalid_jsonl_line` 失败，整个 paper 记忆不可读）。对“跨会话唯一事实源”的记忆文件而言代价较高。
