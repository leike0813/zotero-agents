## B. Findings

### F1 [P2][正确性] src/shared/citationGraphStandalone.ts:464 —— hover-only 节点/边被投影出来但渲染器从不消费，单来源外部引用永远不可见
- 证据：
```
    nodes: projection.defaultNodes,
    edges: projection.defaultEdges,
    hoverOnlyNodes: projection.hoverOnlyNodes,
    hoverOnlyEdges: projection.hoverOnlyEdges,
```
- 分析：`renderCitationGraph` 只把 `projection.defaultNodes/defaultEdges` 放进 `model.nodes/model.edges`，而 `renderSvgCitationGraph` 的 `redrawStage` 仅遍历 `model.nodes` / `model.edges`；全文件对 `hoverOnlyNodes`/`hoverOnlyEdges` 的引用只出现在本行赋值与顶部类型声明。`projectCitationGraphVisibility` 把仅被 1 篇 library paper 引用的外部节点放进 hover-only 集合（citationGraphVisualRules.ts:234-264），因此这类节点既不在默认图中，也不会在 hover/selected 时被补渲染，hover-only 语义完全失效，用户看不到这些引用。
- 建议：在 `redrawStage` 里按 `ownerIds` 命中情况把 `model.hoverOnlyNodes/hoverOnlyEdges` 合并进可见集，或删除 hover-only 分层以免产生“已计算但永不展示”的死路径。
- 置信度：高

### F2 [P2][正确性] src/shared/topicTimelineRenderer.ts:487 —— 轴范围只由论文年份推导，跨度外的事件被静默过滤丢弃
- 证据：
```
  const layout = timelineLayoutFromItems(paperItems);
  const items = [...paperItems, ...eventItems].filter((item) => {
    if (!layout) return false;
    return !!timelineIntervalForYear(layout, item.year);
  });
```
- 分析：`timelineLayoutFromItems(paperItems)` 只用论文年份生成 `minYear..maxYear` 的 interval 列表，随后所有 item（含 milestone event）必须落在这些 interval 中；因此早于最早论文或晚于最晚论文的事件会被 `filter` 掉，永远不进入 `renderTimelineClusters`，而 legend 仍宣称展示 `labels.milestones`。这是用户可见的数据丢失，且无任何日志/占位提示。
- 建议：轴范围取 papers 与 events 年份的并集（或允许事件参与 `timelineLayoutFromItems` 的范围计算），仅对完全非法年份做过滤。
- 置信度：中

### F3 [P3][错误处理] src/shared/synthesisCitationGraphWindow.ts:216 —— 非翻页 slice 合并不改状态却无条件清空 error，可产生 failed 但无错误原因的窗口
- 证据：
```
        : window.status,
      error: undefined,
```
- 分析：`mergePatch(..., advancePage=false)` 时 `status` 保持 `window.status`，但 `error: undefined` 无条件写入。若一个 base 匹配的窗口处于 `status === "failed"` 并收到 slice（例如乱序/重复的增量片段），结果窗口变成 failed 且 error 被抹掉；UI 失去失败 code/reason，而 `retrySynthesisCitationGraphWindow` 仍因 `status === "failed"` 允许“重试”，状态语义不一致。
- 建议：仅在 `advancePage` 时清 error，或在 failed 窗口上拒绝 slice 合并并保留原 error。
- 置信度：中

### F4 [P3][性能] src/shared/citationGraphStandalone.ts:296 —— 每次 hover 重绘都对全量边做两次聚合并全量重建 DOM
- 证据：
```
    const importanceByNodeId = buildCitationGraphNodeImportance(
      model.nodes,
      aggregateCitationGraphVisualEdges(model.edges),
    );
```
- 分析：`redrawStage` 在 line 298 已调用 `aggregateCitationGraphVisualEdges(model.edges)` 生成 `visibleEdges`，line 306-309 又对同一 `model.edges` 再聚合一次；随后 line 382 `graphStage.innerHTML = [...]` 重建全部 `<line>/<circle>` 并重新绑定每个节点的 mouseenter/mouseleave。hover 重绘被 60/80ms 定时器触发，而图窗口的 soft limit 允许 10k 节点/20k 边，单次 hover 的 O(E log E) 双聚合 + 全量 DOM 重建会造成明显卡顿。
- 建议：每次 redraw 只聚合一次并复用（或按 `model` 引用 memo），并考虑对 hover 高亮只改 class/opacity 而非重建整棵 SVG。
- 置信度：中

### F5 [P3][信任边界] src/shared/hostBridgePluginSkillBundleContract.ts:36 —— `isSafeHostBridgePluginSkillBundlePath` 接受 Windows 盘符绝对路径与控制字符
- 证据：
```
    path.length > 0 &&
    !path.includes("\\") &&
    !path.includes("\0") &&
    !path.startsWith("/") &&
    !path.endsWith("/") &&
    !path.split("/").some((part) => !part || part === "." || part === "..")
```
- 分析：`"C:/Windows/System32/x"` 全部通过（无 `\`、不以 `/` 开头、段 `"C:"` 非空且非 `.`/`..`），`"a\nb"` 也通过（只拦了 `\0`）。函数名承诺“safe”，但谓词只覆盖 POSIX 相对路径形状；若消费方在 Windows 上用 `path.resolve/join` 解包，盘符路径可成为绝对路径并逃出解包根，形成 zip-slip 类风险。
- 建议：显式拒绝盘符前缀（如 `/^[A-Za-z]:/`）与控制字符，并用平台相关 `path.relative` + `isAbsolute` 复核最终落点仍在 bundle 根内。
- 置信度：中
