## Findings

### F1 [P2][可维护性] src/workflows/packageHookBundler.ts:25,411 —— `bundleCache` 是无界 process-global Map
- 证据：
  ```ts
  const bundleCache = new Map<string, BundleCacheEntry>();
  ...
  bundleCache.set(cacheKey, { fingerprint, scriptText, moduleCount: orderedModules.length });
  ```
- 分析：键为 `entryFilePath::entryExportName`，`scriptText` 含整段模块转译产物（可达数 MB）；长进程随官方/dev-local 包数量增长，无 LRU/TTL，且不在 `resetWorkflowHostApiForTests` 之外提供按 owner 清理入口。仅 `clearPackageHookBundleCacheForTests` 在 test cleanup 中调用（src/modules/testRuntimeCleanup.ts:94）。
- 建议：限定上限（如 LRU 64 条），或按 owner 维度分桶。
- 置信度：中。

### F2 [P2][设计债] src/workflows/loaderContracts.ts:286-301 —— `allowMixed: false` 校验只拦多必选 kind
- 证据：
  ```ts
  if (selection?.allowMixed === false) {
    const requiredKinds = itemBounds.filter((entry) => entry.min > 0).length;
    if (requiredKinds > 1) { return "...disallows mixed input but requires multiple item kinds"; }
    const hasSingleKindSolution = itemRules.some((rule, index) => {
      if (itemRules.some((other, otherIndex) => otherIndex !== index && !zeroAllowed(other))) return false;
      return rangesOverlap(countBounds(rule), totalBounds);
    });
    ...
  }
  ```
- 分析：当 `parents: {min:1,max:3}`、`attachments: {min:0,max:2}`、`allowMixed: false` 时 validator 不报错（只 parents min>0，attachments 是 zeroAllowed）；运行期用户可选中 1 parent + 1 attachment —— counts 通过、mixed 违约。loaderContracts 只校验静态可满足性，运行期约束靠 `evaluateWorkflowSelection`。
- 建议：README/契约文档明确这一分工，或在 `allowMixed: false` 下禁止 max>0 的非必选 kind。
- 置信度：中。

### F3 [P3][可维护性] src/workflows/packageHookBundler.ts:428-432 —— `__packageHookBundlerTestOnly` 暴露内部到 export 表

### F4 [P2][契约] src/workflows/workflowStoredAttachmentImport.ts:14-22 —— `validateSource` 可选，省略时字节上限静默绕过
- 证据：
  ```ts
  export type WorkflowStoredAttachmentStagerDependencies = {
    ...
    validateSource?: (path: string) => Promise<{ sizeBytes: number } | undefined | void>;
    ...
  };
  ...
  let totalBytes = 0;
  for (const sourcePath of [path, ...companions.map((entry) => entry.sourcePath)]) {
    const validation = await dependencies.validateSource?.(sourcePath);
    totalBytes += Math.max(0, Number(validation?.sizeBytes || 0));
    if (totalBytes > STORED_ATTACHMENT_TOTAL_BYTE_LIMIT) { throw ...; }
  }
  ```
- 分析：API 允许省略 `validateSource`，则 `totalBytes` 始终 0，`STORED_ATTACHMENT_TOTAL_BYTE_LIMIT = 4 GiB` 不触发；companion 数量上限仍守住。当下两个 caller（src/modules/zoteroHostCapabilityBroker.ts:4128, src/workflows/workflowHostOwners.ts:327）都传入了 `validateSource`，但 API 形态使第三方构造易遗漏，导致 staging 目录可被任意尺寸灌入。
- 建议：把 `validateSource` 改为必填，或在 `createWorkflowStoredAttachmentStager` 入口断言非 undefined。
- 置信度：高。

### F5 [P3][契约] src/workflows/workflowStoredAttachmentImport.ts:65-74 —— `cleanupErrors` 与 hook-failure-meta 双约定
- 证据：
  ```ts
  function attachCleanupFailure(primaryError: unknown, cleanupError: unknown) {
    if (!(primaryError instanceof Error)) return;
    try {
      const errorWithCleanup = primaryError as Error & { cleanupErrors?: unknown[] };
      errorWithCleanup.cleanupErrors = [...(errorWithCleanup.cleanupErrors || []), cleanupError];
  ```

- 分析：与 `attachWorkflowHookFailureMeta`（Symbol 键 `__zsWorkflowHookFailureMeta`）走两条约定；消费侧（runtime.ts:773-782）只读 hook meta，不消费 `cleanupErrors`，属埋地雷。
- 建议：要么改用统一 hook-failure-meta 把 cleanup 也带过去，要么在主错误 message 中拼接 cleanup 错误并删除本字段。
- 置信度：中。

### F6 [P1][信任边界] src/workflows/zipBundleReader.ts:62-115 —— zip 解压无 entry 数与总字节上限，存在 zip bomb
- 证据：
  ```ts
  const zipReader = runtime.Cc["@mozilla.org/libjar/zip-reader;1"].createInstance(runtime.Ci.nsIZipReader);
  zipReader.open(runtime.Zotero.File.pathToFile(this.bundlePath));
  try {
    const entries = zipReader.findEntries(null);
    while (entries.hasMore()) {
      ...
      zipReader.extract(entryName, runtime.Zotero.File.pathToFile(targetPath));
    }
  }
  ...
  // Node: command: "unzip", args: ["-q", this.bundlePath, "-d", tmpDir]  或  Expand-Archive -Force
  ```
- 分析：`safeZipEntrySegments` 只防 path traversal，不防 bomb。`findEntries(null)` 循环无 entry 数上限、单 entry 体积无上限；解压过程累计字节无 quota；Zotero runtime 的 `nsIZipReader.extract` 与 Node `unzip -q` / PowerShell `Expand-Archive -Force` 均不限速。临时目录清理由 `recordLeakProbeTempArtifactForTests` 兜底（测试钩子），生产仍可写爆 tmpdir。
- 建议：在解压循环累计 entry 数（>100k 拒绝）和解压字节（>4 GiB/file.ts `transferBytes` 拒绝）；构造时 `statRuntimePathStrict(bundlePath)` 先限制 bundle 文件大小（典型 bomb 上限 256 MiB）。
- 置信度：高。

### F7 [P3][契约] src/workflows/hostApi.ts:617-619 —— `archive.withExtractedZip` 的 `control` 未走 `withDefaultControl`
- 证据：
  ```ts
  archive: {
    measureEntries: (input, control) => archive.measureEntries(input, withDefaultControl(control)),
    writeZipAtomic: (input, control) => archive.writeZipAtomic(input, withDefaultControl(control)),
    withExtractedZip: (input, control, callback) => archive.withExtractedZip(input, control, callback),
  },
  ```
- 分析：archive surface 三个成员里只有 `withExtractedZip` 没有 `withDefaultControl` 包裹，与同 surface 其他成员不一致；caller 不传 control 时 archive 模块拿不到默认取消信号。
- 建议：与其他两个成员一致，包成 `withDefaultControl(control)`。
- 置信度：中。

## 存疑（需补充核对）

- src/workflows/clipboard.ts:114-122 Gecko transferable 解码路径：未在 references 找到 nsITransferable 完整形态样本；本代码兼容 array 与 object 两种形态，意图合理，需在 Mozilla 平台层校对。
- src/workflows/file.ts:96-107 `requirePath` + `normalizeNativeLocalPath`：空字节/Windows 驱动器大小写敏感性委托 `platform/path.ts`，不在本切片审查。
- src/workflows/errorMeta.ts:74-83 从 carrier 读 `capabilitySource`/`executionMode` 兜底：若 caller 把含敏感信息对象 attach 到 error 不在脱敏范围；当前 caller 是 runtime.ts:774-782 自挂载，泄漏面有限。
- src/workflows/workflowHostErrorContract.ts:466-481 assert 在 sanitize 之后：sanitize 截断 `field/opaqueKey/memberOrOperation` 三个 token 键；`limit`/`observed`/`kind` 等保留原值，类型校验后落库，无 schema 漏洞。
