### F1 [P2][契约] src/schemas/zoteroHostMutationSchemas.ts:1107 —— `affectedRefs`/`residualRefs` 的 items 只允许空对象，任何真实 ref 都会让失败结果校验不过
- 证据：
```
    affectedRefs: {
      type: "array",
      items: { type: "object", additionalProperties: false },
    },
```
- 分析：`items` 是「无 `properties` 且 `additionalProperties:false`」的对象，等价于只接受 `{}`。而 `MUTATION_EXECUTION_RESULT_SCHEMA`（1497-1501）把它放进 `failedResultSchema`，`MUTATION_EXECUTE_OUTPUT_SCHEMA`/`MUTATION_GET_OPERATION_OUTPUT_SCHEMA`（1503、1550）都引用失败分支。运行期一旦在 `affectedRefs` 里写入 `{libraryId,key}` 形态的 ref（这是 `$defs/itemRef` 的既有 shape），输出校验就会失败，把一次可解释的 mutation 失败变成 schema 错误，遮蔽真实错误码/恢复语义。对照 `receipt.changes.items` 用的是 `additionalProperties: true`（1052），可见此处并非统一风格而是漏写。
- 建议：把 items 指向 `#/$defs/itemRef`（或显式声明允许的 ref/opaque 字段），使失败结果能表达受影响引用。
- 置信度：中

### 存疑（不作为 finding）
- `src/platform/runtimePlatform.ts:123` `return `${platform}-${architecture}` as SynthesisSidecarRuntimeTarget;`：`as` 断言使 `linux-x86/arm` 等组合即使不在联合类型里也能通过编译，需确认 `SynthesisSidecarRuntimeTarget` 是否包含这四个 linux 组合。

- `src/schemas/zoteroHostMutationSchemas.ts:1027` `MUTATION_EXECUTE_INPUT_SCHEMA` 依赖 `oneOf` 分支隐式 `additionalProperties` 与顶层 `unevaluatedProperties:false` 的交互；不同 validator 实现对「分支未声明 additionalProperties 时未知属性是否算已评估」结论不同，若解释为已评估，则 `expectedRevision`/`token`/`path` 之类的额外字段可能被接受，与「公共 DTO 不接受 expectedRevision/token/path/fileId 写入授权」存在冲突风险（`MUTATION_PUBLIC_INPUT_SCHEMAS_BY_OPERATION` 因显式 `additionalProperties=false` 不受影响）。
- `src/schemas/zoteroHostMutationSchemas.ts:1559-1562`：`MUTATION_INPUT_SCHEMAS_BY_OPERATION` 标注 `Record<MutationPreviewOperation,...>`，而 `MUTATION_PUBLIC_PREVIEW_OUTPUT_SCHEMAS_BY_OPERATION`（1598）与 `MUTATION_PREVIEW_INPUT_SCHEMA`（1032）覆盖全部 `MutationOperation`，需确认 preview 是否真的对 managed_note/literature_artifact 开放。
