### F1 [P1][正确性] src/utils/runtimeBridge.ts:312-321 —— `resolveRuntimeZoteroDetails` 在 override.zotero 已设时仍让 global-var/global-this 进入排序
- 证据：
  ```ts
  if (runtimeBridgeOverride && "zotero" in runtimeBridgeOverride) {
    if (typeof runtimeBridgeOverride.zotero === "undefined") {
      return { zotero: undefined, source: "override", ... };
    }
  }
  const candidates = [];
  if (... runtimeBridgeOverride.zotero) candidates.push({ source: "override", ... });
  const fromGlobalThis = resolveRuntimeGlobal().Zotero;
  const suppressGlobalVarCandidate =
    !!runtimeBridgeOverride?.zotero && typeof fromGlobalThis === "undefined";
  const fromGlobalVar = suppressGlobalVarCandidate ? undefined : readZoteroFromGlobalVar();
  if (fromGlobalVar) candidates.push({ source: "global-var", ... });
  if (fromGlobalThis) candidates.push({ source: "global-this", ... });
  ```
- 分析：override.zotero 存在但得分（Items+Prefs 满分 100）低于 global-var/global-this 时，best score 选择会让 `global-var`/`global-this` 胜出。`suppressGlobalVarCandidate` 只对 global-var 起抑制，对 global-this 无抑制。Zotero runtime 同时存在两类全局是常态；测试场景用 `installRuntimeBridgeOverrideForTests` 时 override 可能失效。
- 建议：override 命中直接返回 override（与 line 314-320 undefined 分支对称），score 仅在没有 override 时生效。
- 置信度：中。

### F3 [P2][正确性] src/utils/sha256.ts:54-61 —— Mozilla `nsICryptoHash` 路径 hex 输出把 base64 串按 charCode 再 hex
- 证据：
  ```ts
  hash.init(nsICryptoHash.SHA256);
  return {
    update(bytes) { hash.update(Array.from(bytes), bytes.byteLength); },
    digestHex() {
      return bytesToHex(
        Uint8Array.from(String(hash.finish(false)), (char) => char.charCodeAt(0)),
      );
    },
  };
  ```
- 分析：`hash.finish(false)` 返回 base64 字符串，`String(...)` 后再 charCode 切片，相当于对 base64 文本做 hex。Node 路径走 `crypto.createHash("sha256").digest("hex")` 是正确的，两条路径产物完全不同；Zotero 7+ Mozilla 路径将得到错误 hash。
- 建议：改用 `hash.finish(true)`（raw bytes），或直接走 `globalThis.crypto.subtle.digest("SHA-256", bytes)`。
- 置信度：高（依据 nsICryptoHash 文档）。

### F6 [P1][信任边界] src/workers/runtimeFileRangeWorker.ts:44-85 —— worker 自身未对 `request.ranges` 长度上限做防御
- 证据：
  ```ts
  const lengths = ranges.map((range) =>
    range.offset >= fileSize ? 0 : Math.min(range.length, fileSize - range.offset),
  );
  const packed = new Uint8Array(lengths.reduce((total, length) => total + length, 0));
  ```
- 分析：reader 端在 `partitionRuntimeFileRanges` 中按 `MAX_BATCH_ENTRIES=1024`/`MAX_BATCH_BYTES=2MiB` 拆分；worker 不再校验。当前 caller 链可信，但 worker 直接接收 `event.data`，防御深度不足；若未来允许其他 host 转发至该 worker，DoS 风险出现。
- 建议：worker 入口加 `ranges.length > MAX_BATCH_ENTRIES || total > MAX_BATCH_BYTES` 防御。
- 置信度：中。

### F12 [P2][时序] src/synthesis/synthesisWorkbenchPanelModel.ts:118-140 —— `resolveTimedStatusbarEntry` 首次 projection 锁定 expiresAt
- 证据：
  ```ts
  let expiresAt = expirations.get(key);

    expiresAt = now + timeoutMs;
    expirations.set(key, expiresAt);
  ```

- 分析：同一 key 多次 projection 共享首次 expiresAt；配合 `pruneStatusbarExpirations` 正确剪除，但时序固定：下个 statusbar 渲染会在最早 expiresAt 触发。legacy 注释明确"first projection starts window"，非 bug。

### F4 [P2][并发] src/utils/wait.ts:29-46 —— `CancellationController` 二次 addEventListener 在 abort 后无防重入
- 证据：
  ```ts
  addEventListener(_type, listener) {
    if (aborted) {
      listener();
      return;
    }
    listeners.add(listener);
  },
  ```
- 分析：handler 内若未主动 `removeEventListener`，再次 `addEventListener` 会立刻再调一次（递归或多次 fire）。`abort()` 内部 `listeners.clear()` 在触发后才清——当前次序安全，但调用方易误用。
- 建议：handler 同步触发时主动 removeEventListener，或 addEventListener 接受 `{ once: true }`。
- 置信度：中。
