### F1 [P1][契约一致性] graph.ts:18 vs citationGraphApplication.ts:88 —— 状态并集同一份定义在两个文件出现
- 证据（graph.ts:18-27）：
  ```
  status:
    | "promoted"
    | "unchanged"
    | "basis_mismatch"
    | "graph_application_busy"
    | "worker_busy"
    | "worker_failed"
    | "invalid_request"
    | "repair_required"
    | "stopping";
  ```
  与 citationGraphApplication.ts:88-97 完全相同的 9 个字面量。citationGraphApplication.ts 在 117 行有 `mutationStatuses` `as const satisfies …` 重复清单。
- 分析：被 `synthesisWorkbenchTab.ts:6` 等大量模块导入的是 `SynthesisGraphCommandResult`（graph.ts），所以两边一旦漂移就只有一半消费者能跟上；枚举 SSOT 已经被破坏。
- 建议：保留 graph.ts 的版本作为 wire DTO，把 citationGraphApplication.ts 的同义并集改为 `import type { … } from "./graph.js"` 并删除本地点。
- 置信度：高

### F3 [P2][契约一致性] exportDelivery.ts:181-201 vs topicApplication.ts:142-158 vs webDavSyncPort.ts:185-202 —— utf8ByteLength 三份近似实现

### F4 [P1][正确性] knowledgeCheckpoint.ts:153-158 + tagVocabularyApplication.ts:138-143 —— 私有 `exact()` 不强制必填
- 证据（tagVocabularyApplication.ts:138-143）：
  ```ts
  function exact(value, fields, location) {
    const allowed = new Set(fields);
    if (Object.keys(value).some((field) => !allowed.has(field))) {
      invalid(`${location}.fields`);
    }
  }
  ```
  common.ts 的 `assertSynthesisExactFields` 同时检查 `required.some((key) => !(key in value))`。
- 分析：`rebuildSynthesisTagVocabularyApplicationSaveRequest` 等 7 个调用都把 `candidate` 之类列为必填字段，但若请求里真没传，allowed.has 检查通过，`input.candidate === undefined`，下游才在 `rebuildSynthesisTagVocabularyApplicationCandidate(undefined)` 用 `object(undefined, "tagCandidate")` 抛 `tagCandidate` 错，定位模糊，且 `rebuildSynthesisKnowledgeCheckpointPayload` 直接 `rebuildSynthesisTagVocabularyApplicationCandidate(row.tagVocabulary)` 会把缺字段抛到 payload 层。
- 建议：两文件 `exact()` 替换为 `assertSynthesisExactFields(value, fields, [], location)`；或新增带 required 参数的本地 helper。
- 置信度：高

### F5 [P2][可维护性] librarySnapshot.ts:1-502 没有 import；503-507 才是 `import {…} from "./common.js"`
- 证据：直接读文件可见全部 502 行代码（类型定义 + 工具函数 + 5 个 `export function rebuildX`）都未导入 `SynthesisClientError/assertSynthesisExactFields/toSynthesisJsonObject`，只有文件末尾 503-507 行才写 `import {...} from "./common.js"`。

### F6 [P2][可维护性] sidecarRuntimeRelease.ts:521-528 —— assertReleaseIdentity 校验 expected SHA256 但未校验 length
- 证据：
  ```ts
  function assertReleaseIdentity(label, actual, expected) {
    if (!SHA256.test(expected) || actual !== expected) {
      throw new Error(`Sidecar release ${label} does not match current identity`);
    }
  }
  ```
- 分析：调用方传入的 expected 都来自 `args.identities.*`，类型上已是 `string`（声明为 `SynthesisSidecarRuntimeReleaseIdentities`），但 runtime 仍可能越过类型校验传入意外长度。`actual !== expected` 已足够抓住长度不一致，但 `expected` 校验在 `actual === expected` 情况下不需要；代码可改为只校验 `actual` 是否为 SHA256。
- 建议：去掉 `!SHA256.test(expected)` 这条无意义检查，或对称加 `!SHA256.test(actual)`。
- 置信度：中（low-impact）
