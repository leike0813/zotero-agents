### B. Findings

### F1 [P1][信任边界] skills_builtin/literature-deep-reading/renderer/templates/markdown-renderer.js:292 —— URL 协议白名单只作用于名为 `href`/`src` 的属性，命名空间属性（`xlink:href`）整条绕过
- 证据：
  ```js
        if (name === "href" || name === "src") {
          const resolved = safeResolvedUrl(value, options);
          if (!resolved) {
            node.removeAttribute(attr.name);
  ```
- 分析：`sanitizeRenderedHtml` 是唯一净化层，而 `PROFILE_OPTIONS.document/synthesis/standaloneDigest` 均为 `html: true`（第 6、26、33 行），即原始 HTML 会进入渲染结果。属性白名单按 `attr.name` 精确比较，`<svg><a xlink:href="javascript:...">` 解析后 `attr.name === "xlink:href"`（不是 `href`），既不删除也不过协议校验；KaTeX/内联 SVG 场景下 `<svg>` 本身也不在 `UNSAFE_TAGS` 内。同源页面中点击该 SVG 链接即执行脚本（deep-reading.js 的 digest 弹窗、synthesis 报告均在同源文档内渲染）。触发条件：任何被渲染 markdown 中含 `html:true` 的可控片段（digest 由 PDF/模型内容生成，属不可信输入）。
- 建议：改为“属性白名单 + 对任意 `href|src|xlink:href|formaction|data|action` 后缀属性统一走 `safeResolvedUrl`”，或对 SVG/命名空间属性一律剥离。
- 置信度：中高

### F2 [P2][信任边界] skills_builtin/literature-deep-reading/renderer/templates/markdown-renderer.js:42 —— 净化器是标签黑名单，`<link rel=stylesheet>`、`<meta http-equiv=refresh>`、`<base>` 均可穿过
- 证据：
  ```js
    const UNSAFE_TAGS =
      "script, style, iframe, frame, frameset, object, embed, applet, form, input, textarea, select, button";
  ```
  ```js
      template.content.querySelectorAll(UNSAFE_TAGS).forEach((node) => {
        node.remove();
  ```
- 分析：黑名单刻意封了 `style`（阻止样式注入），但 `<link rel="stylesheet" href="https://…">` 不在名单内，且 `href` 通过 `ALLOWED_PROTOCOLS` 校验（https 合法）→ 动态插入的 `link[rel=stylesheet]` 会被浏览器加载并生效：可外发请求（Referer/IP 侧信道）、用 CSS 属性选择器做文本外泄、或重排 UI 做钓鱼。`<meta http-equiv="refresh" content="0;url=…">` 与 `<base>` 同样不受限（后者会改变文档 base，影响后续相对链接/锚点）。触发条件同 F1（`html:true` 的 markdown）。
- 建议：改为标签白名单（对齐 DOMPurify 思路），至少显式删除 `link/meta/base/template/svg/foreignObject` 等非内容标签。
- 置信度：中

### F3 [P2][正确性] skills_builtin/literature-deep-reading/renderer/templates/markdown-renderer.js:288 —— 内联样式保留判据只看节点自身 className，KaTeX 布局样式被整片删除
- 证据：
  ```js
          if (name === "style" && !/\bkatex\b/.test(node.className || "")) {
            node.removeAttribute(attr.name);
            return;
          }
  ```
- 分析：判据只对“自身 class 含 katex 的节点”生效（`.katex`、`.katex-html`、`.katex-mathml` 通过），而 KaTeX 的定位/尺寸来自后代节点的内联样式：`.strut{style="height:…"}`、`.vlist{style="height:…"}`、`.pstrut`、以及上/下标层 `style="top:-3.063em;margin-right:0.05em"`。这些 class 不含 `katex` → 一律被删，数学排版（上下标位置、分式/根号高度）将退回基线而对不齐。SVG 节点更绝对：`node.className` 是 `SVGAnimatedString` 对象，正则恒不匹配，即使 `class="katex"` 也会被删样式。所有 profile 都会走 texmath（`window.texmath && window.katex` 时 `parser.use(...)`，与 `html` 选项无关），因此影响面覆盖 document/synthesis/standaloneDigest。
- 建议：改为祖先判定（`node.closest(".katex")`）或对 `mathml/katex` 子树整体跳过属性清理。
- 置信度：高（机制）/ 中（视觉表现程度）

### F4 [P3][契约] skills_builtin/literature-deep-reading/renderer/templates/citation-graph-synthesis-app.js:393 —— `ni()` 写 `cache_status`，而全应用读取的是 `cacheStatus`
