# 具体写回

仅在目标 Zotero 变更已具体确定且无剩余语义推断时使用本旅程。

1. 在写入之前立即重新读取每个目标条目、笔记、集合或附件。
2. 对通用 mutation payload 使用 `mutation preview`。对已知的简单操作，使用语义化的标签、集合、条目、笔记或附加文件命令。
3. 在 Host 拥有的 approval 边界处展示目标引用和拟议效果。
4. 获得 approval 后，保留已应用的结果并重新读取受影响的对象作为完成证据。

当任务仍需分类、生成、多步业务逻辑或声明的可复用合约时，使用 workflow。导航永远不能替代 mutation。原始 `call` 永远不能绕过语义验证或 approval。

如果写入响应不确定，检查 `stateChanged` 和 `handleConsumed`。不要盲目重复。重新读取精确目标并计算剩余差异。遇到拒绝时，报告未写入并停止；拒绝不是选择另一条写入路径的许可。
