# Управление тегами

## Что такое словарь тегов?

Словарь тегов (Tag Vocabulary) — это стандартизированная система тегов, используемая для единообразной аннотации литературы. В отличие от свободных тегов Zotero, теги в контролируемом словаре следуют единым соглашениям об именовании, что облегчает статистику и поиск.

## Аспекты

Каждый тег принадлежит аспекту (измерению). В настоящее время поддерживаются следующие аспекты:

| Аспект | Описание | Пример |
|-------|-------------|---------|
| `field` | Исследовательская область | `field:natural_language_processing` |
| `topic` | Исследовательская тема | `topic:transformer_architecture` |
| `method` | Исследовательский метод | `method:reinforcement_learning` |
| `model` | Использованная модель | `model:gpt-4` |
| `ai_task` | Тип задачи ИИ | `ai_task:text_summarization` |
| `data` | Набор данных | `data:imagenet` |
| `tool` | Инструмент | `tool:python` |
| `status` | Ожидающая задача workflow | `status:need-analysis` |

Формат тега: `^[a-z_]+:[a-zA-Z0-9/_.-]+$`, максимум 120 символов.

## Вкладка «Словарь»

На странице Synthesis Workbench → Теги → Словарь вы можете:

- **Просмотр**: Все определённые канонические теги с отображением статуса, аспекта, псевдонимов и количества использований
- **Добавление**: Создание новых канонических тегов
- **Редактирование**: Изменение метаданных тегов
- **Устаревание**: Отметить тег как устаревший, при необходимости указав тег-замену
- **Импорт JSON**: Импорт словаря тегов из JSON-файла (с предварительным просмотром перед подтверждением)
- **Экспорт JSON**: Экспорт текущего словаря в JSON-файл

Пять встроенных статусов workflow инициализируются при запуске плагина. Их tag, facet, source, состояние устаревания и replacement не могут быть изменены или удалены; notes остаются редактируемыми, а aliases продолжают использовать обычный путь управления. Пользовательские записи `status:*` сохраняют те же элементы управления, что и другие пользовательские записи словаря. Импорты могут обновлять встроенные notes и aliases, но пропуск встроенного или изменение его защищённой идентичности не может удалить или заменить его.

Статусы тегов:
- `active`: Активный
- `deprecated`: Устаревший (имеет тег-замену)
- `warning`: Предупреждение (может потребовать проверки)

## Вкладка «Промежуточные» (ожидающие теги)

Skill **tag-regulator** автоматически анализирует метаданные литературы и генерирует предложения контролируемых тегов, отображаемые на странице «Промежуточные».

### Процесс одобрения

1. Просмотрите список предложенных тегов
2. Для каждого тега вы можете:
   - **Продвинуть**: Добавить тег в канонический словарь
   - **Отклонить**: Отклонить предложение
   - **Очистить промежуточные**: Пакетно отклонить все предложения

### Формат импорта/экспорта

Словарь тегов поддерживает импорт/экспорт в формате JSON (формат TagVocab), что позволяет:

- Миграция системы тегов между библиотеками
- Совместное использование соглашений о тегах в команде
- Резервное копирование и контроль версий

## Связанный Workflow

`status` обозначает ожидающие задачи workflow, а не прогресс чтения. У элемента может быть ноль или несколько статусов. Пять встроенных определений:

- `status:need-metadata-curation`
- `status:need-fulltext`
- `status:need-markdown`
- `status:need-analysis`
- `status:need-deep-reading`

Не нужно запускать Tag Bootstrapper для их создания. Tag Bootstrapper добавляет только пользовательские записи словаря, а [Tag Regulator](#doc/workflows%2Ftag-regulator) может проверять обычные контролируемые теги, но не может добавлять или удалять встроенные статусы workflow у элементов литературы. Ни один из двух workflow не может вывести встроенный статус из темы, языка, метаданных или полного текста статьи.

| Событие | Добавить к элементу | Удалить у элемента |
|---------|---------------------|---------------------|
| Search создаёт элемент | Markdown, analysis и deep reading; metadata/fulltext, когда результат их требует | — |
| Search повторно использует элемент | Только metadata/fulltext, явно требуемые этим результатом | — |
| Metadata Curator успешен или подтверждает отсутствие изменений | — | Metadata curation |
| MinerU записывает и прикрепляет Markdown | — | Markdown и fulltext |
| Literature Analysis записывает формальные артефакты | — | Analysis |
| Literature Deep Reading записывает и прикрепляет HTML | — | Deep reading |

Неудачные, пропущенные, отменённые или неприменённые запуски не очищают статус. Если артефакт успешен, но очистка статуса не удалась, артефакт сохраняется, и запуск сообщает частичное предупреждение. Ручное добавление PDF не удаляет `status:need-fulltext` автоматически.
