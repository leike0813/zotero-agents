# Literature Metadata Curator

## 目的

選択された Zotero 親アイテムの書誌メタデータクエリ、修正、補完を行います。このワークフローは、タイトル大文字表記の不一致、著者不足、不完全なジャーナル/巻/ページフィールド、不完全な DOI/ISBN エントリ、誤って設定されたアイテムタイプなどのケースを処理します。

## 入力

| パラメータ | 必須 | 説明 |
| --- | --- | --- |

ユーザー設定可能なパラメータはありません。Zotero アイテムリストから正確に 1 つの親アイテムを選択してください。添付ファイルや複数アイテムは受け付けられません。

## 動作

ワークフローはユーザー確認なしで完全に自動実行されます。2 つのパスに従います：

1. **ローカルファストパス**：アイテムに DOI、ISBN、または DOI、arXiv、PubMed 識別子に決定的に解決される URL がある場合、ワークフローは `runtime.hostApi.metadata.translateIdentifier`（制御された読み取り専用 Zotero `Translate.Search` ファサード）を呼び出します。候補識別子が一致し、貴重な書誌情報を含む場合、結果が直接書き戻されます。
2. **Skill-Runner フォールバック**：信頼できる識別子が存在しない、ローカル検索が結果を返さない、トランスレータが失敗する、候補が信頼できない、または識別子が一致しない場合、ワークフローは `literature-metadata-search` スキルを実行して軽量なウェブベースのメタデータ取得を行います。

両方のパスは同じ正規結果形式と同じ apply ハンドラを共有します。

### 書き戻しルール

ワークフローは親アイテムの書誌フィールドを更新します：

- タイトル、DOI、ISBN、ISSN、URL、要約、日付、言語、ライブラリカタログ
- ジャーナル/会議/書籍/学位論文/レポートフィールド（ジャーナル名、巻/号/ページ、出版社、会議名、学校、レポートタイプなど）
- 作成者（著者、機関著者など）
- 高信頼度の証拠でサポートされる場合の `itemType`（例：ジャーナル記事が学位論文に修正）

ワークフローは添付ファイル、ノート、タグ、コレクション、関連アイテム、PDF ファイル、またはウェブスナップショットを**変更しません**。

安定した識別子がない場合、ワークフローは既存のタイトルを上書きするかアイテムタイプを変更するのは次の場合のみです：候補が同じ直接の作品であることが証明でき、少なくとも 2 つの独立した書誌シグナルが一致し、権威あるランディングページが裏付ける。コンテナタイトルは作品タイトルを置き換えるのではなく、適切なコンテナフィールドに書き込まれます。低信頼度、競合する候補、または疑わしいのみの結果はスキップされます。

## 出力と適用

メタデータの変更は選択された Zotero 親アイテムに直接適用されます。中間確認ステップは不要です。

## モデル推奨

- **ファストパスヒット**（DOI/ISBN/サポートされた URL 識別子が存在）：バックエンドモデル不要。
- **`literature-metadata-search` へのフォールバック**：ウェブ検索機能を備えたモデルが推奨されます。タスクは軽量な取得と証拠検証です — 長文執筆能力は不要ですが、同音異義語、プレプリントと公開バージョン、論文と学位論文、異なる版を区別する必要があります。

## 依存関係

- **バックエンド**: Skill-Runner（ローカル検索ミス後のフォールバック用）
- **スキル**: `literature-metadata-search`
- **Zotero Host API**: `metadata.translateIdentifier`（制御された読み取り専用ファストパス）
- **Apply Handler**: `handlers.parent.updateMetadata`
